# 阶段 5 节点 16：受限状态断言与变量提取

完成日期：2026-07-15

## 交付内容

- `EXTRACT` 步骤仅支持 `LAST_STATUS_CODE`，将状态码写入本次 Runner 的内存变量；后续受限请求可以引用该变量。
- `ASSERT` 步骤仅支持最近请求状态码精确断言（100–599）。非 2xx 响应可以由显式断言接管；未被断言覆盖的非 2xx 会使任务失败。
- 运行时工件升级为 v2 严格顺序步骤流，只包含 `REQUEST`、`EXTRACT`、`ASSERT` 所必需的字段。
- 新增 Redis 步骤结果流及 MySQL V20，执行详情展示提取和断言的步骤、结果、已观察状态码、Runner 与时间。

## 安全边界

- 提取变量只保留在 Runner 内存，绝不落库、写入 Redis Stream、日志或浏览器响应。
- 不会解析、保存或展示响应正文、响应头、Cookie、异常文本、密钥或用户脚本。
- 脚本、请求头、Cookie、重定向、数据库步骤、条件/循环和环境密钥继续不在受限 Runner 范围内。
- 动态变量替换完成后仍由 Runner 执行 Origin 白名单与地址网络边界校验。
- 局部变量只能在对应提取步骤之后使用，不能覆盖冻结变量，也不能位于 URL 的 scheme、host 或 port；状态断言值必须是 100–599 的整数。

## 验证范围

- 前端 lint、单元测试和生产构建。
- Node Runner 协议与执行测试，覆盖提取后引用、精确断言与无变量值泄露。
- Spring Boot 集成测试，覆盖 V20、工件 v2、冻结步骤校验、非法额外结果字段拒绝和权限读取。
