# TestHub 安装即用：执行历史持续双向同步

日期：2026-10-12。上一模块“缺陷执行用例关联同步”已获用户审核通过。本模块按用户确认的“两端可编辑，变更双向同步”完成实现、最终源码／内部 Mac arm64 包验收及清理，并已获用户审核通过。

## 使用与边界

桌面“测试计划与执行”页和应用菜单新增“执行历史同步”。先登录账号服务、选择项目，读取两端已有批次，逐一确认一对一对应关系，预览数量后确认绑定。计划编号须相同，批次内按用例编号、步骤序号及原历史步骤正文匹配，不按同名自动合并。未配对批次分别复制为新批次，后续新批次按固定来源标识识别；预览和默认取消不写业务记录。

两端继续在原有执行页面编辑步骤实际结果／状态和用例结果；本轮补齐执行备注编辑与保存。同步完整批次的结果、步骤、备注、开始／完成及结果更新时间。时间随原有真实结果操作变化，沿用原有执行状态聚合和重新打开逻辑；同步只复制记录，不启动测试。

已有执行批次、执行用例、步骤的物理 ID、创建元数据及缺陷关联保留。已有用例／步骤布局不同暂停整批，不删除或重新生成结构。新批次保留源创建时间，创建人和同步审计记录目标实际账号；不复制另一端人员 ID，改动结果的原执行人／步骤操作人标记清空，未改动的本端归因保留。两端时钟差异时保证更新时间不早于原创建时间，普通编辑和原有历史迁移仍可继续。

显式启用后应用运行时每 30 秒检查，也可立即同步、暂停／恢复、解除绑定。首次对应批次内容不同或双端同时修改须选择整批历史，不自动混合结果。冲突界面显示实际结果、备注、步骤与时间；确认期间内容或实际对象变化拒绝旧选择。计划、用例、批次、执行用例或步骤缺失／重建暂停相关批次；一端删除不会删除另一端或自动重建。含本端项目／文件链接的历史暂停，须先显式迁移并核对。其他有效批次仍可同步。

## 协议与保护

新增 `GET/POST /api/v1/projects/{projectId}/functional/history/sync`，`FUNCTIONAL_HISTORY_SYNC` / 1。快照含便携历史、物理对象／依赖 ID 映射及创建时间；提交包含固定来源标识、便携定义、来源创建时间和预期版本。创建时间不作为已有批次的可变合并字段，避免因原有批次创建时间不同产生永久冲突。旧执行、迁移及缺陷协议保持兼容。

H2 V36／MySQL V93 增加可空 `functional_test_run.sync_key`、项目内来源唯一索引及持久回执，旧迁移不改。正常旧批次以原 ID 作为来源，新复制批次以固定来源键识别，不依赖显示名。快照 REPEATABLE READ，写入 READ COMMITTED；与原有执行和资产操作共享项目锁，锁后再读版本。全批预校验，业务写入、审计与回执同事务，失败回滚。回执保留提交时实际批次、用例、步骤及依赖 ID，响应丢失后安全重放，不覆盖提交后的编辑。

每项目最多 100 个批次、1000 条执行用例、5000 条步骤；依赖计划及用例各最多 1000 条。快照／合并最多 3 MiB，请求／响应最多 4 MiB；超限拒绝，不裁剪，缺失基线仍纳入预算。

本机 `functional-history-sync.bin` 使用 OS 加密、原子保存、0600 权限，保存配对、基线、身份和待提交请求。账号／服务切换、CSRF、项目／角色边界、磁盘失败、不可信 IPC 帧均有检查；远程页面只允许打开原生工具，读取与提交仅可信原生页调用。十七类真实绑定独立共存，备份恢复后全部持久暂停并要求重新预览。
