# 阶段 5 · 节点 19：受限流程控制执行

## 完成内容

- API 自动化场景增加可校验的流程控制语法：`WAIT`、`CONDITION`、`LOOP`。
- `WAIT` 只允许固定毫秒延迟，并受任务截止时间约束；取消可在等待期间中断。
- `CONDITION` 只允许最近 HTTP 状态码与 100–599 常量进行等于/不等于比较；条件不满足时仅跳过紧随的请求。
- `LOOP` 只允许紧随请求并以 1–10 次总执行次数重复该请求；控制面和 Runner 都限制展开后最多 300 次请求。
- 短时 Runner 工件升级到版本 3，并通过 `HTTP_FLOW_CONTROL_V1` 能力标识进行兼容协商；旧 Runner 不识别时保持预检模式。
- Runner 仅上报固定控制日志与既有脱敏 HTTP/断言结果，不记录条件值、循环数据、请求/响应内容、变量值或密钥。
- 自动化编排页提供状态条件与有界循环的专用配置表单，并说明相邻步骤规则。

## 安全边界

- 这不是通用工作流或脚本引擎：不支持 JavaScript、任意表达式、动态循环、并发、嵌套循环、数据库步骤或响应正文解析。
- 所有网络请求继续使用精确 Origin 白名单、私有地址拦截、DNS 地址固定和任务截止时间限制。
- 控制面只生成声明式短时工件，不执行用户提供的代码。

## 验证

- `ApiAutomationScenarioFlowTests`：步骤语法和不安全流程结构校验。
- `ApiRunnerRuntimeConfigurationFlowTests`：版本 3 工件及流程控制字段的签名领取与转换。
- API Runner 单元测试：等待、条件通过/跳过、有界循环、脱敏结果与旧安全边界。
- 前端 lint、测试、生产构建、全量 Spring Boot 回归和浏览器预览在本节点交付前执行。
