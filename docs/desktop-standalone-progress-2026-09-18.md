# 本地会话与安全状态持久化（2026-09-18）

后续进展：见 [本地持久任务队列与 Runner 通信验证](desktop-standalone-progress-2026-09-18-broker.md)。以下保留会话阶段当时的事实与证据。

本阶段完成桌面模式的登录会话、注册限流、防重放记录和执行租约持久化。Redis 不可达时，这些流程及个人工作区访问已通过真实 HTTP 验证。任务流和 Runner 心跳仍依赖 Redis，因此整个应用尚未脱离 Redis，也尚未生成可分发的独立安装包。

## 实现

- `DesktopSessionConfiguration` 仅在 `desktop` profile 启用 Spring Session JDBC；原 Redis Session 配置仅在其他 profile 启用。保留原 Cookie 名称、CSRF、登录时轮换会话 ID、8 小时空闲过期和退出登录逻辑。
- Spring Session JDBC 使用 Spring Boot 管理的 3.5.6 版本。会话表结构来自该依赖内置 H2 脚本，字段及行为遵循 [Spring Session JDBC 官方说明](https://docs.spring.io/spring-session/reference/configuration/jdbc.html)。不另行实现 Cookie 认证协议。
- 新增桌面迁移 `V2__local_sessions_and_runtime_state.sql`，增加会话、会话属性和带有效期的安全状态表。保留既有 V1 和全部 MySQL 历史迁移。验证从桌面 V1 升至 V2 后已有组织数据仍在。
- `ExpiringStateStore` 抽离原子占位、读取、固定时间窗计数和删除；服务模式继续使用原 Redis 键和过期策略，桌面使用本地 H2。
- 四类 Runner 内部请求防重放、API 自动化 Webhook 防重放、API 执行租约和注册限流使用该接口。租约仍只保存摘要，不保存可直接使用的租约凭证。Runner 心跳尚未迁入此接口。
- 本地安全状态通过独立事务提交，不能随业务失败回滚；否则失败请求使用过的 nonce 可能再次被接受。本地文件库只由一个 JVM 持有，单实例状态写入在提交期间串行化；后台每分钟清理到期记录。
- 状态操作使用独立的短连接，避免请求已占用业务连接时，为独立事务再次申请业务连接而耗尽连接池。既有应用业务事务和 API 错误/权限契约保留。
- 原流程测试仅切换 nonce/租约夹具的存储接口，保留业务断言；Redis 心跳和任务流夹具仍使用原路径。

前端和 Electron 本阶段没有改动，未重复执行此前已通过的前端/桌面测试。两个专用 QA 容器和 8081 进程在验证后停止，保留测试数据；未停止用户原开发服务，未替换已安装 App，未提交、推送或发布安装包。
