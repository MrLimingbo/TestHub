# 阶段 4.3.2.1：手动 Mock 基础报告

## 交付范围

- 提供项目级 Mock 服务管理：新建服务、启停服务、查看服务下的规则。
- 提供手动 Mock 规则：HTTP 方法、精确路径、响应状态、响应头和响应体。
- 提供无需登录的公开运行时地址：`/api/v1/mock/{serverKey}` 与其子路径。
- 增加 `mock_server`、`mock_rule` 两张 MySQL 迁移表，所有记录均包含组织和项目作用域。
- 管理端操作写入审计事件；运行时请求不持久化、不进入控制面业务日志。

## 本节点边界

- 只按 HTTP 方法与完整路径精确匹配；不匹配查询参数、请求头、请求体或脚本。
- 每项目最多 20 个服务，每服务最多 200 条规则；响应体上限 512 KB，响应头最多 32 个。
- 公开运行时拒绝危险响应头，防止 Mock 结果影响 TestHub 自身会话与连接控制。
- 不运行任何用户脚本；规则 Mock、智能示例 Mock、资产化 Mock 与协作能力留待后续节点。

## 验证记录

- `./mvnw -q -pl services/platform-api test`：通过（包含 `MockServiceFlowTests`）。
- `npx pnpm@10.13.1 lint && npx pnpm@10.13.1 test && npx pnpm@10.13.1 build`：通过。
- 浏览器验收：在 `/mock` 新建“浏览器验收订单 Mock”，创建 `GET /orders` 规则，管理页展示公开地址、启用状态和规则行。
- 运行时验收：请求公开地址的 `/orders` 返回 `200`、`application/json` 和配置的响应体；方法不匹配与停用服务由后端自动化测试断言为 `404 MOCK_RULE_NOT_FOUND`。

## 用户预览步骤

1. 打开 `/mock`，确认当前项目后新建 Mock 服务。
2. 在服务详情中复制公开调用地址，创建一条规则，例如 `GET /orders` 与状态码 `200`。
3. 调用“公开调用地址 + /orders”，检查响应体；停用服务后再次调用，预期收到 404。
