# 阶段 5 · 节点 28：失败策略的隔离 Runner 语义

## 已交付

- 运行时工件在签名租约通道中携带冻结修订的 `failureStrategy`；缺失字段按兼容规则默认为 `STOP`，不改变 v4 工件契约。
- `STOP` 保持首个状态码断言或任一隔离脚本失败后停止的既有行为。
- `CONTINUE` 会在状态码断言或后置脚本失败后继续执行后续受限步骤，追加固定的 `FAILURE_CONTINUED` 审计日志，并在全部可执行步骤完成后将执行收敛为 `FAILED`。
- 前置脚本失败和没有可用 HTTP 状态的传输失败始终停止，避免在变量未准备或无可审阅状态的情况下继续。
- 场景编辑器与创建弹窗明确展示“失败后继续（最终仍失败）”，并针对当前策略说明可继续与始终停止的边界。

## 安全边界

- Runner 只接受 `STOP`、`CONTINUE` 两个固定枚举；其他值在领取工件时拒绝。
- `FAILURE_CONTINUED` 的级别和消息是控制面与 Runner 双方固定白名单，不携带 URL、请求正文、响应、变量、密钥、脚本文本或异常详情。
- 策略仅存在于签名绑定、短时的运行时工件和冻结场景修订；不进入任务 Stream、执行日志自由文本或浏览器结果接口。

## 验证

- API Runner 单元测试覆盖失败状态断言在 `CONTINUE` 下继续执行后续请求、先写入失败步骤结果、最终写入固定失败事件和无 URL 泄露。
- 控制面集成测试断言短时工件携带冻结失败策略。
- 前端 lint、Vitest、生产构建以及控制面 Maven 回归将在节点验收前完成。
