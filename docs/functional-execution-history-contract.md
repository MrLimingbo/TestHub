# 功能执行历史标题与测试计划编号契约

更新：2026-11-03；对应已批准规则D08-A、D07-A。历史编号、步骤、状态及权限沿用原有规则。

## 计划编号

计划创建后编号不可修改。PUT仍必须提供planCode，先按创建规则trim、转大写并检查格式；等于原编号时可编辑其他字段，不同时400并保持原计划、关联和成功审计不变。省略、null、空白及非法格式仍拒绝。编辑页面只读显示并发送原编号。

## 执行标题来源

新批次在创建事务内保存每个用例的title_snapshot，与该次读取的步骤一起冻结。运行用例API的title优先取快照；titleSource为SNAPSHOT。原资产改名不会改变它。

旧记录不回填；title_snapshot为空时title显示当前资产标题，titleSource为CURRENT_ASSET，页面明确提示旧记录未保存标题快照。用例编号仍是原有动态引用语义，本规则不修改编号或删除约束。

MySQL V113和桌面H2 V57只新增可空列，没有历史数据UPDATE。数据库迁移不等于已安装桌面应用升级验证。

## 历史交换与兼容

迁移历史RunCase与历史同步CaseResult都可以携带可选titleSnapshot。存在时必须是非空白字符串、最多200字符；不把数字、布尔或容器转成标题。旧格式缺失字段保留缺失，不能从目标当前标题补全。序列化缺失值时省略该字段，保持旧资料及旧回执的原序列化形状。

已有历史的titleSnapshot是布局的一部分：同步不能修改、补造或移除它，冲突返回409并保持布局和结果；备注及原允许修改的执行结果继续按原规则同步。

功能迁移capabilities新增historyTitleSnapshots=true。包含非空标题快照的HTTP GET导出，客户端还须显式发送titleSnapshots=true；未声明则400，提示更新客户端。旧客户端不能因此静默把新标题快照转发给不支持的目标。无标题快照的旧历史仍可按旧参数导出。

桌面迁移先核对目标能力：支持时在历史导出URL附加titleSnapshots=true；目标未声明而来源含快照则停止，不发送业务迁移。历史同步快照新增titleSnapshotsSupported=true，桌面在两端交换前检查；不支持时要求更新两端。传输对象的标题快照不被投影或丢弃。

这些是可选扩展及能力协商，不改变迁移1至8的范围版本，也不把titleSnapshot添加到不含执行历史的资料范围。旧格式无此字段可继续读取；有快照的资料不可降级为无快照历史。
