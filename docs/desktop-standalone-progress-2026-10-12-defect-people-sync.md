# TestHub 安装即用：缺陷负责人／抄送双向同步

日期：2026-10-12。上一模块“缺陷工作流同步”已获用户审核通过。本轮按用户确认的“绑定时逐一确认成员对应关系”推进人员同步，实施、最终源码／内部包验收和阶段清理已完成，并已于 2026-10-12 获用户审核通过。

## 使用与数据边界

桌面“缺陷与交换”页和应用菜单新增“缺陷人员同步”。连接账号服务并登录后选择两端项目，读取已有成员，逐一选择一对一对应关系，再预览及确认；读取和预览不写业务记录，确认默认取消。配对页及确认详情显示姓名、账号和邮箱，不按显示名、相同账号或邮箱自动推断。同一成员不能重复配对，可只配对部分成员；未配对人员会阻断涉及的缺陷。

只读取所选项目已有且启用、未删除的成员；沿用既有缺陷权限规则，将当前实际操作账号纳入可选人员。同步本身不创建账号、不邀请成员、不授予或变更权限。绑定中的人员资料和对应关系只在本机操作系统加密文件中保存，提交只发送目标端人员 ID；不读取其他项目的账号、密码、手机号或系统账户列表。

显式启用后应用运行期间每 30 秒检查，可立即同步、暂停／恢复、解除绑定和核对冲突。按不可变缺陷编号匹配本端实际对象，将源人员 ID 映射为已确认的目标人员 ID，负责人和完整抄送集合共同同步，支持明确清空。抄送视为集合，排序去重。

相同人员集合不改写旧记录；只修改抄送时保留原指派人。负责人变化由目标实际同步账号执行指派并记录为指派人，清空负责人同时清空指派人，不复制源端指派归因。状态、确认、解决方案、解决／关闭人员与时间、创建信息、正文、目录、优先级、来源、三类资产关联、文件及执行历史保留各端。既有缺陷编辑和工作流同步保留原契约。

首次人员集合不同、双端修改需选择完整集合；确认期间内容、人员资格或实际对象 ID 变化时拒绝旧选择。缺陷缺失不创建／删除，同编号重建后人员不同需重新核对，相同人员可安全刷新基线。成员缺失、停用、删除、未配对或账号／邮箱身份变化会暂停涉及的缺陷；检查当前及基线人员，防止把成员失效误认为用户明确清空。显示名修改不改变身份。重新建立对应关系须解除旧绑定后再预览，不删除两端资料；其他有效缺陷可继续同步。

## 协议、权限及持久性

新增 `GET/POST /api/v1/projects/{projectId}/functional/defect-people/sync`，协议 `FUNCTIONAL_DEFECT_PEOPLE_SYNC` / 1。定义严格限定 `assigneeId`、`ccUserIds`；快照包含实际缺陷 ID、当前可用成员及已有失效引用标记。每项目最多 100 条缺陷、100 条项目成员关系（另可含当前操作账号），抄送最多 100 人；合并含缺失基线最多 100 条、快照／合并最多 3 MiB，请求／响应最多 4 MiB，超限拒绝而不裁剪。

H2 V34／MySQL V91 新增持久回执，旧迁移不修改。快照 REPEATABLE READ；写入 READ COMMITTED，先共享项目锁，再按顺序锁涉及的账号和当前成员关系，锁后重新读取资格和快照版本，避免普通编辑、停用和移除竞态。快照版本包含实际缺陷 ID、人员、原指派人、成员身份和成员关系。全批预校验，专用 SQL 只修改人员及更新人，业务写入、审计和回执同事务；失败回滚。

持久请求保存目标端原始映射 ID、版本及请求标识。响应丢失后重放提交时回执及实际对象 ID，不覆盖之后的手动修改；回执转换回已确认的本地人员基线。账号／服务切换、CSRF、角色／项目边界、磁盘写入失败和不可信 IPC 帧受保护；远程页面只能打开原生工具，人员读取和写入仅可信原生页可调用。独立 OS 加密状态文件 `functional-defect-people-sync.bin` 原子写入，权限 0600。十五类绑定独立共存，恢复备份全部持久暂停并要求重新预览。
