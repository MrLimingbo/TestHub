# 原生只读预览取消契约

2026-11-03，对应D24-A / OBS-15-E001。范围为公共同步安装器34组context/preview及原生迁移11组context/prepare，加34个冷status分支，共124个处理器；已加载status仍只读内存。冷status仅准备本地元数据，后端启动放在后续受保护操作中。打开页面前的既有登录与运行时预检、bind/run/resolve等写流程、commit上传、备份恢复和应用整体退出沿用原流程。

ReadOperations只跟踪当前操作，使用工作区原有exclusive锁。每次操作持有独立ID与AbortController，绑定原生setup窗口、主框架及准确页面；取消请求必须匹配当前操作ID，旧ID不能取消后续操作。操作信号通过AsyncLocalStorage传到JSON、二进制及会话读取，与既有超时、调用方signal合并；只读范围内不允许业务写请求。所有同步模块和迁移入口复用此契约，各模块资料合并与提交算法保持。

取消请求立即使本操作预览plan失效。取消不会提前完成Promise或清全局锁：须等底层请求、读取或不可立即中断的本地步骤实际结束，并由原exclusive的finally释放锁后，才发布CANCELLED和允许关闭。迟到plan再次失效，结果不返回为成功token；正常完成保留可用预览。网络错误、超时、取消和成功均清理本操作导航/销毁监听器及读取资源。

原生页面有共享“取消预览”控件，点击立即显示正在取消；5秒仍未终止则显示“终止未确认，正在等待；工作区仍锁定”。状态不是强制5秒截止，不以隐藏窗口、杀进程或清空别人的锁代替终止。窗口关闭请求会触发同样的取消，并等操作结束再尝试关闭；如已有其他写操作，原关闭保护继续有效。

页面离开通过webContents的did-start-navigation主框架事件使操作失效，随后取消实际读取。采用事件details.isMainFrame字段；Electron也会对程序发起的导航发出该事件，参见[官方导航事件定义](https://www.electronjs.org/docs/latest/api/web-contents#event-did-start-navigation)。取消控件只注入原生预览页面，遵守原CSP；原远程页面preload不开放取消API。旧轮询、离页响应与失效操作不能更新新状态。

验收中的1秒反馈和5秒协作终止目标，均使用可中断受控夹具测量；不可立即中断的夹具应保持锁并报告等待。真实离屏Electron使用生产协调器、IPC安装器、preload和原生页面，业务传输受控；Node矩阵覆盖其余入口。该证据不代表完整安装版、发行包或升级退出验证。

升级关闭超时仍是独立未确认风险，不由本契约或普通预览关闭结果解除。
