## 当前资产与持久化边界

| 数据 | 当前保存位置 | 下一阶段要求 |
| --- | --- | --- |
| 接口目录 | `api_catalog` | 保留树形层级、空目录、排序与项目边界 |
| 接口定义 | `api_definition` | 保留方法、路径、名称、状态及当前版本引用 |
| 接口版本 | `api_definition_version` | 复制全部快照及发布状态；旧人员引用与新归属需明确处理 |
| 接口用例 | `api_definition_case` | 请求快照、校验、响应、环境代码需验证引用与脱敏边界 |
| 调试历史 | `ApiDebugHistory` 持久化仓库 | 区分历史结果与可回放草稿，不伪造执行记录 |
| 快捷请求目录、隐藏项、目录映射 | `api_workspace_preferences`，按项目和用户隔离 | 已持久化；旧 origin 数据不删除，仅导入当前可访问的旧状态 |
| 快捷请求副本、跨页临时草稿 | sessionStorage | 先核对临时语义与敏感请求内容，不直接改成明文永久保存 |
| 接口树显示方式 | `api_workspace_preferences` | 与目录共同保存，revision 防止并发覆盖 |
| 环境、变量及凭据 | 项目配置模块 | 账号迁移需显式范围与依赖检查，不能默默复制凭据 |

现有 OpenAPI 导出读取当前版本；已有 Postman/HAR 交换也不是完整原生资产备份。不能用交换格式往返替代全部版本、目录及历史的显式账号迁移。现已新增独立 API_DEFINITIONS V1 原生迁移入口；它覆盖目录、全部定义版本和用例及可选文件，仍不包括调试历史、gRPC 描述符和环境凭据，不能据此宣布接口模块全部完成。

## 已复现：同一工作区重启后快捷请求目录不可见

本地服务在 `local-runtime.cjs` 使用 `--server.port=0`；`main.cjs` 虽使用固定 Electron partition，窗口仍直接加载带动态端口的 HTTP 地址。localStorage 由 origin（包括端口）隔离，因此固定 partition 并不保证跨端口读取同一份 localStorage。

真实 Electron 复现使用全新独立用户目录及本地数据库：

1. 启动本地工作区，在实际快捷请求 localStorage 键中注入一条测试目录，确认页面显示它。这里验证既有数据的读取与重启保留，不声称测试了新建按钮。
2. 关闭应用，用同一用户目录再次启动，确认项目 ID 不变，但本地服务端口改变。
3. 新 origin 下相同 localStorage 键为 null，页面该目录数量为 0。

证据：`.testhub/api-module-20260928/restart-storage.mjs`、`restart-storage.log`、`restart-storage-result.json`。这不是数据库目录被删除：项目仍保留，测试未删除旧 origin 下的浏览器存储；问题是新 origin 无法访问此前存储。

## 初始实施顺序与验收计划（保留审计记录）

1. 优先修复工作区界面状态的持久化。倾向按项目和用户保存到受权限保护的数据库记录，避免依赖端口，并使现有数据库备份能够覆盖这些状态；需先完成具体接口、输入约束及并发方案。
2. 不使用固定端口掩盖问题，也不直接把请求副本和临时敏感草稿改成永久存储。旧浏览器状态保持原样；仅凭新 origin 无法自动恢复旧 origin 数据，旧数据导入/恢复需要单独验证，不能宣称全部恢复。
3. 回归：真实新建/重命名/移动/取消、同端口刷新、不同端口冷启动、备份恢复、不同用户与项目隔离、并发更新及错误反馈；补充 Electron 下快捷目录使用 window.prompt 的兼容性检查，此项尚未复现，不能当作已确认缺陷。
4. 目录持久化闭环后，推进接口定义、完整版本和用例的默认关闭、可预览、可重试的原生账号迁移；再按明确依赖处理环境、文件和调试历史。

断点：`.testhub/api-module-20260928/CONTINUE.md`。下一步应从上述已复现缺陷的实现与回归继续，不重跑已完成的功能测试 V6/V7/V8 全阶段。
