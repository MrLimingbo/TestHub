# TestHub 安装即用：缺陷需求／用例关联双向同步

日期：2026-10-10。上一模块“项目版本与构建定义同步”已获用户审核通过。本轮只推进缺陷需求／用例关联的持续双向同步。实现、最终源码／内部包验收和阶段清理已完成，并于 2026-10-12 获用户审核通过。

## 实现与使用边界

桌面“缺陷与交换”页及应用菜单新增“缺陷关联同步”。本地和账号模式可打开独立绑定页，网页端保留原关联编辑入口。先连接账号服务并登录，再选择本地与账号项目；预览不写业务数据，确认默认取消。启用后应用运行期间每 30 秒检查一次，支持立即同步、暂停／恢复、逐条核对和解除绑定。导航较宽时在导航自身横向滚动，避免挤出整页。

按项目内缺陷编号匹配，以需求和用例编号映射目标端自己的资产 ID；同步完整需求集合与用例集合，支持主动清空。资产须先存在于两端，本模块不创建缺陷、需求或用例，不传播资产删除。首次内容不同、双端修改、引用恢复或同编号重建后内容不同，需要人工选择完整集合；确认期间资料变化时停止写入并要求重新核对。

未变化关联的 ID、创建人和创建时间保留；新关联使用目标端实际账号和新 ID。执行用例（RUN_CASE）关联、缺陷正文、状态、确认、指派／抄送／解决人员及时间、执行步骤、文件和项目版本保留各端。相同关联集合不重建原关联；取消定义关联不触碰执行用例关联或缺陷原记录。

原有删除需求／用例操作可能留下失效的缺陷关联。本轮保留原删除行为和旧记录：快照单独标记该缺陷不可同步，提示在本端缺陷详情中核对并解除失效关联；读取不删除旧数据，其他缺陷仍可继续。资产删除导致的关联缺失不会被误认为主动清空；原同步基线与旧引用标识保留，恢复引用后仍需核对。多轮引用删除时保留所有未解决基线依赖，清除不再需要的旧引用缓存。

## 协议与兼容保护

新增 `GET/POST /api/v1/projects/{projectId}/functional/defect-links/sync`，协议 `FUNCTIONAL_DEFECT_LINK_SYNC` / 1。快照包含需求／用例完整编号集合、各端实际引用 ID 和不可同步缺陷编号；引用 ID 用于检测重建，不作为另一端创建资产的输入。每项目每类缺陷／需求／用例最多 100 条，每缺陷每类关联最多 100 条；定义关联总量最多 20,000 条。快照及合并定义不超过 3 MiB，请求／响应不超过 4 MiB；编号限定为已有规范，不裁剪超限数据。

新增 H2 V32 / MySQL V89 持久回执表，旧迁移不修改。写入共享项目锁，比较包含资产与关联真实 ID 的快照版本，整批预校验引用和权限；关联修改、审计与回执同事务提交，失败整批回滚。普通关联写入与同步串行；等待项目锁后重新检查版本。回执保存提交时的引用 ID，响应丢失后以同一请求恢复；不重做已经提交的关联，不覆盖后来编辑，重试前引用重建仍需核对。

独立 OS 加密文件 `functional-defect-link-sync.bin` 原子写入、权限 0600，损坏时保留原数据并报错。可信原生页可操作绑定，远程业务页只能打开原生入口。账号／服务切换阻止出站修改。十三种同步独立绑定，恢复备份前全部持久暂停并标记需要解除旧绑定、重新预览。

主要实现为 `FunctionalDefectLinkSyncService.java` / `FunctionalDefectLinkSyncController.java`、`FunctionalDefectService.replaceDefinitionLinks` / `FunctionalDefectRepository.findDefinitionLinks`、`functional-defect-link-sync.cjs` / IPC / 原生 UI，以及主进程、preload、桌面入口和新数据库迁移。后端流程、桌面引擎、前端入口及请求体限制均补充回归。
