# 接口自动化触发配置双向同步（已审核通过）

用户已确认：新复制的定时计划／Webhook 默认停用；已有目标触发器收到配置修改后先停用，由用户在目标核对后重新启用；Webhook 密钥不跨端传输，新副本在目标独立生成。本模块按该范围实现 `API_AUTOMATION_TRIGGER_SYNC / 1`，接口自动化页及原生菜单提供“触发配置同步”入口。

双向同步定时计划的名称、场景／执行配置集名称、Cron、时区、超时和失败阈值，以及 Webhook 名称和场景。按触发类型与名称对应，场景及配置集必须已存在且名称唯一，引用映射为接收端自己的 ID；两端需具备项目管理员权限。引用资料可提前使用已完成的基础资料／场景同步准备，触发配置同步本身不修改这些资料。每类最多 200 条，定义总量 2 MiB，提交请求最多 4 MiB；超限明确暂停，不静默截断。

新增副本和收到定义修改的目标触发器停用。只改变来源启用状态不会向另一端传播；定义未变时保留目标手工启用状态。已有计划的失败计数、上次执行 ID、结果、时间与创建信息保留；同步不新建、取消或重跑任务，已运行任务继续结束。迟到的成功／失败结果不会把已暂停计划重新启用。目标配置修订及状态纳入快照检查；页面提交原修订时间，拒绝用陈旧表单覆盖同步后的配置或启用状态。

Webhook 新副本显示“待生成本端密钥”，启用按钮不可用。用户确认生成后只展示一次本端密钥，仍需手工核对并启用。已有本端密钥不替换；已生成密钥不允许重复生成，丢失时沿用撤销后新建的处理方式。密钥、加密密文、签名地址、启用状态、失败计数、原执行信息及结果不进入同步定义；项目切换、取消对话框及组件卸载隔离迟到密钥响应，避免在其他项目显示。

单端修改持续同步，双端修改要求选择保留一端；选择后接收端仍停用。删除、改名、同名重建、重复名称或场景／配置集缺失暂停对应配置，无关触发器继续同步；不自动删除或重建旧配置。定义与本端来源标识、引用标识共同追踪，已恢复或重建的同名资料需再次核对。状态、冲突及待确认请求加密保存；响应丢失后用相同请求重试，稳定回执不会重复创建、重新停用用户已启用的未变配置或更换密钥。账号／服务变化停止写入，恢复备份后持久暂停并要求重新绑定。

新增 H2 V42／MySQL V99：Webhook `secret_ready` 默认 TRUE，使已有记录保持原有可用密钥；新增项目与账号范围的同步回执表。接口具备权限、CSRF、项目锁、目标修订、严格字段验证与整批事务保护。未知密钥／启用字段拒绝，声明长度与 chunked 请求边界均限制。Quartz 的同步调整在数据库提交后执行；实际 SQL 约束拒绝时整批数据库写入与运行中的 Quartz 注册保持原状。
