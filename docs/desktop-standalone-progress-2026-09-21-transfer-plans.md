# 本地测试计划迁入账号：2026-09-21 验证记录

在上一阶段目录、需求和用例迁移的基础上，增加可选的测试计划迁移。原生页面默认不勾选“同时迁移测试计划及用例关联”；勾选后，预览和最终确认均列出计划数量。修改勾选范围会使旧预览失效，必须重新预览。

本阶段已经验证：迁入的计划可在独立网页端创建新的执行批次，并记录用例结果。原本地资产和原执行批次保持不变。这里仍是一次性复制，不代表账号离线双向同步或完整资产迁移已经完成。

同时补齐在线模式冷启动后的迁移入口：打开原生迁移页会自动准备本地来源，保持当前账号网页和登录状态，无需先切回本地再连接服务。初始化失败会在原生页面提示错误；初始化期间退出应用会等待当前操作并停止其本地进程。

## 实现与兼容

- 保留计划编号、名称、说明、状态、目录层级及排序、计划用例顺序；所有目标资产采用新 ID，计划关联映射到此次迁入的用例。未分类计划仍为未分类，空计划可迁移。
- 计划定义、目录、需求、用例和迁移收据共用一个事务。计划编号冲突、外部/重复用例引用或后置计划校验失败时，整批回滚；不覆盖已有记录。
- 目标计划不包含原执行批次、步骤结果和执行人员；在网页端新建批次时，复用现有执行服务初始化全新的未执行记录。原始作者、附件、缺陷、标签、自定义字段及其他模块仍不在本阶段迁移范围内，页面已明确说明。
- `GET /api/v1/projects/{projectId}/functional/transfer` 默认仍返回 V1；显式 `?version=2` 才导出计划及 PLANS 目录。目标能力接口保留 `version:1`，增加 `versions:[1,2]`。旧客户端继续使用原有定义迁移。
- 新客户端只有在用户勾选计划且目标明确支持 V2 时才请求 V2。旧目标不支持计划时，在读取来源资产前给出错误，不静默丢弃计划；取消勾选可继续使用 V1。
- V1 不序列化新增的 `plans` 字段。测试独立构造原始四字段快照，比较序列化字节、SHA-256 和旧版收据返回形状，验证已有请求重试仍能识别。V2 收据增加实际计划数量。
- 保留原预览账号绑定、CSRF、权限检查、重复请求防重及原生确认机制。V2 限制为合计 5000 条需求/用例/计划、5000 个来源目录、64 层目录、50000 条计划用例关联和 8 MiB 序列化快照。
- 本阶段无需新增数据库迁移，桌面仍为 V5、MySQL 仍为 V62。

主要代码：`FunctionalTransferService.java`、`FunctionalTransferController.java`、`apps/desktop/app/src/functional-transfer.cjs`、`main.cjs`、`ui/transfer.html`、`ui/transfer-renderer.js` 和复选框样式。测试扩展于 `FunctionalTransferFlowTests.java` 与 `apps/desktop/test/functional-transfer.test.cjs`。
