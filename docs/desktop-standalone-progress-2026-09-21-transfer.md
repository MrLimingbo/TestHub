# 本地基础资料迁入账号：2026-09-21 验证记录

本阶段在现有独立桌面改造上增加显式的本地资料复制：用户先进入本地工作区，再连接账号服务并登录，在用户菜单选择“本地资料迁入账号”，选择来源和目标项目，预览后确认上传。独立浏览器登录同一账号可看到迁入的需求和用例。本地原件保持不变。

这只是功能测试基础资料的一次性迁移，不代表全模块资产迁移或离线双向同步已完成。正式分发门槛仍未通过。

## 范围与行为

- 复制需求/用例目录的名称、层级和排序，以及需求、用例的编号、标题、状态、优先级、正文、用例类型和需求关联。目标生成新的 ID，并在相应目录范围内建立“本地迁入-迁移记录ID”根目录。
- 不复制附件、计划、执行历史、缺陷、其他测试模块、用户身份、密钥及设置；新记录归实际登录账号所有。正文中的附件链接不重写。页面在确认前明确列出这些边界。
- 预览只读取来源资料，并检查目标服务版本、项目和写入权限；不会上传来源数据。最终系统确认框展示账号、目标项目、数量和服务地址。
- 原生进程持有预览快照；预览与在线账号、服务、窗口、本地实例绑定，有效期十分钟。提交前再检查账号，服务端也校验预期用户，避免预览后切换账号造成误传。
- 同编号冲突整批返回 409；后续任一资产校验失败同样回滚整个事务，不留下部分目录或需求。不覆盖现有记录。
- 服务端收据按目标项目、用户、请求键隔离。同一请求重试返回原收据；请求键对应不同内容时拒绝；并发重试只提交一份。客户端在结果不确定时保留同一请求键和快照，可在原预览有效期内重试。
- 目前请求计划只保存在原生进程内，重启后需重新预览；不声明支持跨重启断点续传。后续编辑不会自动同步。
- 单次上限为 8 MiB 序列化快照、5000 个来源目录、合计 5000 条需求/用例、64 层来源目录。该限制不等同于 HTTP 请求解析前的流式限额。

## 代码入口

- `apps/desktop/app/src/functional-transfer.cjs`：预览、账号绑定、提交与网络适配。
- `apps/desktop/app/src/main.cjs`：原生页面 IPC、可信来源校验、用户确认及生命周期互斥；`remote-preload.cjs` 只暴露打开入口，数据迁移操作只允许原生页面调用。
- `apps/desktop/app/src/ui/transfer.html`、`transfer-renderer.js`：项目选择与迁移状态；`src/layouts/AppShell.vue` 和 `src/utils/desktopWorkspace.ts`：在线桌面入口，普通网页不显示该菜单。
