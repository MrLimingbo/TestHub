# 阶段 6 · 节点 3：真实 JMeter 执行、指标流与报告

完成日期：2026-07-19

## 交付范围

- 新增执行指标表与迁移 `V32__performance_execution_metrics.sql`；指标按组织、项目、执行、Runner 和线程组持久化，支持总览与线程组时间序列。
- 控制面新增受签名保护的 JMeter 运行时工件端点。队列消息仍不携带目标地址；只有已通过心跳验证、且声明可执行的 Runner 才能领取运行时工件。
- JMeter Runner 生成非 GUI JMX、创建受限工作目录、执行进程、轮询 JTL、回传 Redis Stream 指标，并支持取消时先 `SIGTERM`、再受控升级为 `SIGKILL`。
- Runner 对运行时工件进行严格校验：协议版本、任务绑定、线程组上限、URL 格式和 Runner 精确 Origin 白名单均不通过即拒绝执行。
- JMeter 子进程采用固定 `64m–512m` 堆边界，并同时移除环境代理和禁用 JVM 系统代理，防止主机代理绕开 Runner 的网络白名单。
- 性能测试页面增加 Runner 可执行状态、两秒任务刷新、执行报告抽屉、TPS/P95/累计错误趋势图、聚合摘要和时间线日志；关闭报告会停止刷新并清理当前报告状态。

## 浏览器验收

- 创建并保留计划“JMeter 实跑验收 · 本机健康检查”，目标唯一为 `http://127.0.0.1:8080/actuator/health`，1 线程、0 秒加压、10 秒持续时间。
- 首次真实启动发现 JVM 参数兼容问题；修复为 JMeter 支持范围内的固定堆限制后，任务可受控启动。
- 第二次执行发现 macOS 系统代理会把本机 URL 代理到 `127.0.0.1:7897`。Runner 现同时清除代理环境变量并关闭 JVM 系统代理；此问题被记录为一次成功完成但 100% 业务错误的历史任务，便于审计。
- 最终任务 `01KXWHB2518WFN255E2J90ZM78` 已完成：3,967 样本、峰值 TPS 395.26、P95 6ms、错误率 0.00%、峰值并发 1。报告页可显示指标趋势和完整执行日志。
- 历史任务不会删除：包括一次 JVM 启动失败和一次代理导致的 404，方便检查失败分类、审计记录和修复后的成功执行。
