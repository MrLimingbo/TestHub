# 标签与字段定义迁入账号：2026-09-22 验证记录

本阶段在目录、需求、用例、测试计划迁移之上，增加独立勾选的项目标签与自定义字段定义迁移。未勾选时继续原有迁移范围；勾选后显示标签、字段定义、标签关联数量。未选计划时排除计划字段及计划标签关联。

迁入后，独立网页可以读取这些配置、编辑迁入的字段，并用迁入的计划创建新执行批次。原本地定义和执行记录保持完整。这仍是一次性复制；不代表完整资产迁移或账号离线双向同步已完成。

## 实现范围

- 项目标签字典包含未绑定标签；保留名称、颜色，为目标创建新 ID。需求、用例、所选计划的标签关联只映射至本次迁入资产和新标签。
- 保留所选资产类型的字段名称、标识、类型、必填设置、选项顺序。当前迁移范围仅为字段定义，不包含填写值、旧作者或旧时间戳。
- 通过已有 `FunctionalGovernanceService` 创建记录，加入原资产迁移事务；冲突、非法字段、错误引用导致整批回滚，迁移收据也回滚。
- 目标已有同名标签或同资产类型/字段标识时整批拒绝，即便配置相同也不自动合并。后续增量迁移和冲突合并尚未实现。
- `FunctionalTransferGovernance.java` 负责便携配置、引用验证、冲突检测与新 ID 关联；`FunctionalTransferService.java` 负责版本、整体范围和事务；原生 `functional-transfer.cjs` 负责能力协商、预览及重复提交保护。复用现有治理数据库表，无新增数据库迁移。

## 协议兼容与边界

- 默认 GET 仍为 V1；V2 保留计划迁移。能力接口保留 `version:1`，支持版本扩充至 `[1,2,3]`。
- 只有勾选标签/字段且目标明确支持 V3，桌面才请求 `?version=3&includePlans=true|false`。不支持时在读取源资产前报错，不静默漏掉所选配置。
- V1/V2 不序列化新 `governance` 字段，旧版序列化字节、快照摘要和已有收据重试仍兼容。V3 收据额外记录标签/字段/关联数量。
- 保留账号绑定、项目读写权限、CSRF、原生确认、十分钟预览有效期、原请求幂等重试；变更项目或勾选范围使旧预览失效。关闭应用后不保留未完成预览。
- 数量限制：资产及标签/字段合计 5000，来源目录 5000、层级 64；标签关联与计划用例关联分别最多 50000；序列化快照 8 MiB。验证范围外引用、重复绑定、重复标识/名称/字段键；未进行极限规模性能验收。
