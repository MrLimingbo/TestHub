## 同步行为

Web UI 页面及应用菜单新增“历史同步”和“报告产物同步”，两个绑定分别选择本地／账号项目、预览范围并确认；原有 Web UI 资料同步保持原有行为。

历史绑定同步已结束执行的只读结构化报告，保留原项目／执行标识、执行时的场景名称和版本、浏览器名称／类型、关联计划名称、重试来源和次数、状态／结果代码、原始时间，以及步骤标识、序号、类型、名称、结果、耗时和发生时间。不包含页面地址、选择器、输入、变量、错误原文、Runner 或操作人员身份、截图、Trace、视频。目标端无需先存在对应的当前场景，两个来源的同名场景不会合并执行；编辑当前场景不改写旧执行版本。

原执行端仍负责运行任务和接收迟到步骤结果。新增步骤修订计数：同一步骤被 Runner 再次写入时，即使发生时间相同，历史来源修订也会变化，随后更新已有只读副本。旧步骤迁移后初始计数为 1，原有公开报告字段和执行协议保持不变。

报告产物绑定还需单独勾选原始内容发送确认，并通过默认取消的原生确认框。截图、Trace 和视频原样传输，不脱敏，可能包含页面、输入、响应、访问地址及其他敏感内容；仅绑定结构化历史不会发送这些文件。每个产物按原项目、执行和原文件 ID 区分，保留同次执行的多张截图，不按类型或文件名合并。

Web UI“同步历史”可查看只读步骤报告并下载结构化 JSON；原始产物另列大小、归档时间、来源文件和 SHA-256。截图／视频仅在点击预览后加载，Trace 仅供附件下载；不在控制面执行 Trace。产物列表每页 12 个。任务中心将导入历史标为“Web UI 同步历史”，原生执行和导入历史使用不同类型，不创建、取消、重试或重放任务，不重复计入现有质量统计。

## 一致性与边界

- 每项目最多 1000 条来源历史，单份 1 MiB、最多 300 步，每批最多 20 条和 4 MiB；超过范围暂停并说明原因，不截断复制。
- 每项目最多 2000 个产物，单文件沿用现有 Web UI 归档上限 25 MiB，每轮最多 20 个，剩余显示数量并留待后续检查；JSON 请求上限 35 MiB，在解析 Base64 前限制声明和流式字节数。
- 共享二进制传输器只为本模块显式开放 25 MiB；原有项目文件／JMeter 的默认上限仍为 20 MiB，空文件也仍需显式允许。
- 原始产物只有在两端都已有对应已结束执行历史时复制，不创建替代执行；已有原生记录由原 Runner 管理。
- 传输和新下载接口先核对完整长度及 SHA-256，再提供附件／预览。PNG／WebM 可预览，Trace 预览返回 406；响应含私有禁止缓存与 `nosniff` 头。
- 历史缺失、不同孤立副本、已同步产物缺失或内容变化时暂停对应来源，不覆盖原始产物、不自动重建、不传播删除；正常独立文件仍可继续。
- 服务、账号、项目权限必须与绑定相符。查看者可读取但不可导入；写入需要 CSRF。远端网页只可打开原生窗口，不能直接调用传输控制；原生窗口验证发送方、主框架和页面地址。
- 待确认请求加密保存并使用固定请求标识重试，原始 Base64 不出现在界面状态中。登录失效保留待确认请求，重新登录原账号后继续；暂停／解除绑定保留两端历史和文件。
- 恢复备份前持久暂停两个新绑定，再次重启仍要求重新核对绑定。对象写入使用独立持久意向、外层事务锁、提交／回滚后回收和陈旧意向恢复，保护已提交文件。

新增 H2 `V45__ui_history_artifact_sync.sql` 和 MySQL `V102__ui_history_artifact_sync.sql`，增加步骤修订列、历史归档／回执及产物归档／回执／写入意向表。归档保留组织和项目范围，来源标识为追溯信息；不引用目标当前场景或伪造目标执行。
