# 移动应用文件持续同步与关联

日期：2026-10-19。移动端只读历史与 PNG 产物模块已获审核，本轮继续独立的移动应用文件模块。前一模块的未提交代码保留；本轮没有收到新的 Git 提交／推送指令，没有自动提交。已有 `main` 提交仍为 `0ff58f2`。

## 范围与使用

应用文件字节通过既有“项目文件同步”传输和配对，新增加“移动应用文件关联同步”，独立勾选、预览并确认后，才更新两端应用记录中的文件关联。

1. 先确认同一服务、账号、本地项目及账号项目的项目文件绑定，完成文件复制；两端已有文件须按原方式逐一配对并核对大小和 SHA-256。同名独立文件保留，不能凭文件名猜测 ID。
2. 确认移动端资料，使两端存在名称、大小写及平台一致的应用。新关联绑定不创建应用、设备或场景。
3. 单独确认应用文件关联，双向将原应用的文件映射到目标实际文件 ID。已有相同关联作为基线，一端更换为已配对的新文件后可更新另一端；两端不同关联或双边改动需选择已核对版本。
4. 文件或应用缺失、文件未配对／内容变化、应用改名／平台不同、清空已同步关联时暂停核对。不会跨端删除、清空或重建。项目文件绑定暂停、解除、账号／服务／范围不一致时不更新关联。

关联更新保留启停状态、应用包标识、版本标签和其他配置，仅递增目标本端编辑版本；已排队执行使用原冻结清单。文件字节只读，不替换已有文件；不安装 APK／IPA，不启动 Appium、模拟器或真机，也不触发执行。文件可包含敏感业务内容，仍按已确认的文件绑定发送原字节，关联绑定不另开未经确认的二进制传输通道。

继承项目文件每文件 20 MiB、每项目 1000 文件的既有范围，关联最多 100 个应用，每轮处理 20 个，剩余下轮继续；关联协议索引／请求最多 1 MiB。大于 20 MiB 的包目前需手动处理或以后扩展文件传输协议，本模块不声称支持无限大小安装文件。包的签名、可安装性及真机兼容性未验收。

## 数据与恢复

新增 `/api/v1/projects/{project}/mobile-automation/application-files/sync`，保持移动端资料 V1 及原文件同步协议不变。服务端校验登录主体、项目写入角色、CSRF、项目锁、应用版本／旧关联、整体索引修订和目标文件实际字节。目标文件已损坏时，即便缓存 SHA 未变化也拒绝关联。

桌面从当前有效项目文件配对读取对应 ID，提交前核对两端实际字节，重新检查应用和文件配对。基线、冲突与待确认请求单独加密保存；元数据请求不携带原文件字节。UUID 回执在 H2 V47／MySQL V104 新表中持久化；响应丢失后用原请求确认，不重复递增应用版本。账号会话过期或文件配对失效时保留请求并停止发送，需核对后恢复。

备份恢复后，文件同步和应用关联绑定均停用并要求重新绑定，跨重启持久生效。关联请求回滚时仅回滚应用关联与回执，不删除已有文件。缺失已确认的应用或文件不会被回执重试重建。

## 20 MiB 上传边界修复

首轮真实包在 20 MiB 文件上传处被既有 multipart 总请求限制阻断，未计作通过；自有工作区与进程已清理。原配置将整个表单和单文件都限制为 20 MiB，表单头会使完整边界文件超限。真实 HTTP 回归复现了请求被拒绝／连接关闭。

现保留单文件 20 MiB，将 multipart 总请求上限设为 21 MiB，仅为表单头留出空间，并将明确的上传超限异常映射为共享错误信封的 413，而非通用 500。新增随机回环 HTTP 端口的真实 multipart 测试，验证恰好 20 MiB 成功、超出 1 字节返回 413／`REQUEST_REJECTED`，且仅保存一个合规文件；测试数据独立清理。修复后重新构建并验收最终包，旧包结果单独留档。

## 代码与验收入口

- 后端：`MobileApplicationFileSyncService`／`Controller`，H2 V47／MySQL V104；复用项目文件存储，新增 JSON 预解析限流。
- 桌面：独立 `mobile-application-file-sync` 加密状态、原生页面、可信 IPC、菜单、30 秒检查及恢复钩子；普通账号页面仅可打开原生工具，不能直接调用同步写入。
- 页面：移动端新增“应用文件关联同步”入口，原有配置和执行流程保留。
- `scripts/desktop/accept-mobile-application-file-sync.mjs`：真实 Mac 目录包、独立双后端、隐藏离屏桌面和无头网页；文件传输、20 MiB 边界、应用 ID 映射、冲突、故障与备份恢复。
- `scripts/desktop/accept-mobile-application-file-upgrade.mjs`：显式 V46 后端生成原生移动端协议夹具和已有应用文件关联，独立副本升级至 V47，核对原配置、身份、执行报告、PNG、文件和回执重试。

验收脚本接收独立 `--app`、全新 `--output`、已校验 `--browser-cache` 及其目录内的无头 `--chromium`；升级另需 `--baseline-backend`。先复制缓存至阶段目录再校验，不使用用户工作区进行验收。APK／IPA 内容是受控字节夹具；升级中的执行历史为受控协议夹具，均不算真实设备安装／执行通过。
