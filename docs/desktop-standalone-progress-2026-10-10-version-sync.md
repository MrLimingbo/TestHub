# TestHub 安装即用：项目版本与构建定义同步

日期：2026-10-10。上一模块“功能缺陷基本资料同步”已获用户审核通过。本轮只推进项目版本与构建定义的离线持续双向同步。实现、最终源码／内部包验收与阶段清理均已完成，并于 2026-10-10 获用户审核通过。

## 本轮实现

桌面“版本管理”页及应用菜单新增“版本与构建同步”。本地和账号模式可打开独立绑定页，网页端不显示原生入口。先连接服务并登录账号，再选择本地与账号项目；预览上传、下载与冲突数量，并通过默认取消的确认才启用。应用运行期间每 30 秒检查一次，支持立即同步、暂停／恢复、解除绑定和逐条选择冲突版本。

按项目内版本号匹配，同步完整有序构建号列表、计划发布日期和版本描述；构建列表、日期与描述支持显式清空。已有发布状态、实际发布日期、本端 ID、显示编号、创建人和创建时间保留各端，更新人是本端实际操作账号。新版本为 `UNSTARTED`，实际发布日期为空。不同内容首次合并、双端修改、同版本号删除／重建需要核对；不传播删除，不自动重建已经缺失的版本。

原版本号允许修改。客户端使用本端对象 ID 识别已同步版本的改名，暂停旧名称与新名称，不将其当成另一条新增版本自动复制。恢复名称后内容不同时需要重新核对；也可解除绑定并重新预览。大小写不同必须先统一名称。原响应丢失时持久重试同一请求，回执包含已提交对象 ID，防止重试前同名重建后误用新对象。

正文含 `/api/v1/projects/` 或其编码形式的本端项目／文件链接时，暂停该版本自动同步并提示显式迁移核对。其他不含该引用的版本可以继续同步。不复制文件或执行历史，不提交执行；原功能资料、缺陷、人员、关联和执行记录保持原有行为。

## 兼容性与保护

新增 `GET/POST /api/v1/projects/{projectId}/versions/sync`，协议 `PROJECT_VERSION_SYNC` / 1。每项目最多 100 个版本，每版本最多 50 个构建；版本号与构建号最多 100 字符，描述保持已有 20,000 字符上限。完整快照及合并定义不超过 3 MiB，请求／响应不超过 4 MiB。读取先检查数据库数量和原始文本字节，完整快照再次限额；不裁剪资料。日期、完整字段、未知受保护字段、重复构建、大小写重复与数据库唯一约束严格校验，构建顺序原样保留。

原版本 CRUD、状态切换与功能显式迁移接口保持契约。版本写入加入共同项目锁与 READ COMMITTED；同步比较快照后整批预校验，审计与持久回执一起提交，失败整批回滚。已有版本使用专用定义更新 SQL，只写构建号、计划日期、描述和实际更新人，不重写发布状态或实际日期。相同定义不修改旧记录和时间，旧请求回执重放不会覆盖后来编辑。

新增 H2 `V31` / MySQL `V88` 回执表，旧迁移不修改。独立 OS 加密文件 `project-version-sync.bin` 原子写入，权限 0600；解密失败保留原数据并报错。账号／服务切换阻止出站修改。十二种同步独立绑定；恢复备份前全部持久暂停并标记需要重新预览绑定。
