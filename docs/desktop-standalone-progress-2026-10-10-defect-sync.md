# TestHub 安装即用：功能缺陷基本资料同步

日期：2026-10-10。上一模块“功能资产标签关联同步”已获用户审核通过。本轮只推进缺陷基本资料与交付目录的离线持续双向同步，完成后等待本模块审核。实现、最终源码／内部包验收及阶段清理均已完成，并于 2026-10-10 获用户审核通过。

## 本轮实现

桌面“缺陷与交换”页及应用菜单新增“缺陷资料同步”。本地和账号模式均可打开独立绑定页；网页端不显示原生入口。先连接账号服务并登录，选择本地与账号项目，预览上传、下载和冲突数量，经过默认取消的确认后才绑定。默认不上传任何资料；应用运行期间每 30 秒检查一次，支持暂停、恢复、解除、立即同步和逐条选择冲突版本。

按不可变缺陷编号匹配资料，交付目录按完整路径匹配，目录结构、排序及缺陷目录关联在目标重映射为本端 ID。同步标题、截止日期、Bug 类型、关键词、浏览器、操作系统、严重程度、优先级、来源、外部链接和重现步骤。浏览器与操作系统为完整集合，按名称规范排序；选填目录、日期和链接可以显式清空。首次同编号内容不同及双端修改均需要选择，确认时资料再次变化会拒绝过期选择。目录冲突、缺失或大小写不同会暂停依赖资料。

已有状态、是否确认、解决方案、负责人、指派人、抄送成员、解决／关闭人员与时间、ID、显示编号、创建人和创建时间保留各端；更新人记录本端实际操作账号。新缺陷为 `OPEN`、未确认、无负责人、无抄送、无解决／关闭记录，创建人是目标端账号。需求、用例及执行用例关联不复制，已有三类关联与运行步骤快照保留；文件、工件、版本及执行不在此同步范围内。

删除不传播，不自动重新创建已同步后缺失的资料。缺失后同编号恢复、以及轮询之间同编号删除／重建造成 ID 变化时，内容不同需要重新核对；两端相同内容可更新基线。回执保存已提交对象的 ID，防止响应丢失、服务重启和目标重建叠加后误用同编号的新对象。正文或外部链接包含本端 `/api/v1/projects/` 项目／文件链接的资料暂停自动同步，继续使用显式迁移并核对引用。

## 兼容性与保护

新增 `GET/POST /api/v1/projects/{projectId}/functional/defects/sync`，协议 `FUNCTIONAL_DEFECT_SYNC` / 1。每项目最多 100 条缺陷、100 条交付目录，目录最多 16 层，重现步骤最多 20,000 字符，完整快照及合并资料不超过 3 MiB，请求／响应不超过 4 MiB。读取先检查数据库数量和正文原始字节数，完整快照再次限额；不裁剪大项目，不截断正文。严格校验字段、日期、选项、大小写重复、引用及未知受保护字段。

原缺陷 CRUD、流转、关联和导入接口保持原有契约。其写入加入共同项目锁，使用 READ COMMITTED；同步先比较版本与身份，整批校验后才写入，审计和回执在同一事务内。已有记录的同步更新使用专用基本资料 SQL，不调用会改写流转信息的整对象更新。相同定义不改动旧记录和时间；同一请求的持久回执可并发安全重放，不覆盖后续编辑。

新增 H2 `V30` / MySQL `V87` 回执表，旧迁移不改写。独立 OS 加密文件 `functional-defect-sync.bin` 原子写入，权限 0600；不能解密时保留原数据并报错，不回退成空记录。账号／服务切换阻止出站修改。任务、配置、通知、Mock、性能、Web UI、移动端、功能基础资料、治理定义、标签关联和缺陷基本资料共十一种独立真实绑定；备份恢复前全部持久暂停，恢复后必须解除旧绑定并重新预览。
