# 阶段 5 · 节点 5.7：变量引用预检与来源锁定

## 交付内容

- 执行提交前扫描所有步骤字符串配置中的 `{{变量名}}` 引用。
- 未定义引用会在创建执行记录、执行清单和 Runner Outbox 之前被拒绝。
- 执行清单升级至版本 2，新增每个已解析引用的最终来源、是否为密钥及 `stepId.configKey` 使用位置。
- 变量来源优先级固定为：`ENVIRONMENT_SECRET`、`SCENARIO`、`PROJECT_PARAMETER`。
- 任务详情新增“已解析引用”视图；变量取值、请求 URL、请求头和步骤配置文本始终不会展示。

## 安全边界

- 预检只读取场景变量名、项目参数名和环境密钥元数据，不读取或解密参数/密钥值。
- 未绑定变量不会产生任何执行记录、执行清单、Outbox 消息或 Runner Stream 负载。
- Runner 仍没有获取运行时配置或密钥的控制面通道，也不会执行网络请求、数据库操作或脚本。

## 验收建议

1. 在接口自动化场景的请求地址中使用已有的 `{{baseUrl}}`，提交预检并打开任务详情。
2. 检查“已解析引用”中显示 `baseUrl` 的来源和 `request-order.url` 位置，且没有显示其取值。
3. 将地址改为 `{{missingToken}}` 并保存后提交，确认页面提示变量未定义，且任务列表没有新增记录。
