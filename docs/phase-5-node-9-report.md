# 阶段 5 · 节点 5.9：Runner 防重放认证与能力发现

## 交付内容

- 可信 API Runner 可使用心跳密钥对内部能力发现请求签名。
- 控制面验证 Runner 当前签名心跳、请求时间窗口、恒定时间 HMAC 比较与 Redis 一次性 nonce；重放、篡改或未可信 Runner 均被统一拒绝。
- Runner 可选配置 `TESTHUB_CONTROL_PLANE_URL`，未同时配置 `RUNNER_HEARTBEAT_KEY` 时启动配置直接拒绝，避免降级为匿名回连。
- 能力接口仅返回固定的安全预检与签名发现能力；运行时配置和用户内容执行明确保持关闭。
- 接口自动化页面说明可信 Runner 已具备能力发现资格，但不表示可获得敏感运行时配置。

## 安全边界

- 内部接口不使用浏览器 Cookie、用户 PAT 或静态仓库令牌。
- HMAC 负载不含任务、项目、变量、密钥、请求体或脚本文本。
- nonce 仅存储 Redis 2 分钟，且不包含任何业务数据；它用于拒绝重放，不用于授权持久化。
- 本节点不下发执行工件、环境密钥、数据库凭据或用户内容，也不改变 `executionEnabled=false`。

## 验收建议

1. 访问接口自动化页，确认 Runner 面板显示“运行时配置交接和用户内容执行仍保持关闭”。
2. 生产环境向控制面与 Runner 注入相同心跳密钥，并额外向 Runner 注入控制面根地址；确认 Runner 日志出现签名能力发现成功。
3. 重复同一签名请求或修改签名，确认控制面返回 401，且不返回任何配置内容。
