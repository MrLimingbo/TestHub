# 阶段 7 · 节点 1：项目质量工作台

## 本节点交付

- 将工作台从静态演示替换为项目范围的真实质量看板：功能用例、接口资产、接口自动化场景、待解决缺陷、已判定执行、通过率和严重缺陷均由 MySQL 聚合。
- 新增 `GET /api/v1/projects/{projectId}/dashboard?days=7|30`；读取前执行项目级读取权限校验，统计周期限制为 7–90 天。
- 质量趋势按完成时间汇总功能用例执行、接口自动化执行和性能任务；取消的任务不进入“已判定执行”或通过率。
- 看板展示最近 8 条项目审计活动，只包含动作、资源类型、操作者和时间，不返回审计详情、请求/响应、认证信息或环境密钥。
- 工作台支持切换可访问项目和近 7/30 天周期；ECharts 趋势图、执行分布、质量状态与审计动态均随真实 API 结果刷新。

## 统计口径

- 功能测试以已执行的用例结果为单位；`PASSED` 为通过，`FAILED` 与 `BLOCKED` 为未通过。
- 接口自动化和性能测试以结束任务为单位；`SUCCEEDED` 为通过，`FAILED`、`REJECTED`、`TIMED_OUT` 为未通过。
- 性能阈值的细粒度判定仍在性能报告中查看；工作台只汇总任务终态，避免误把聚合看板当作单场压测报告。
- 健康状态优先由未解决严重缺陷判定为风险；无严重缺陷时，再依据所选周期是否存在未通过执行判定“需要关注”或“质量稳定”。
