# 阶段 5 · 节点 22：公共步骤与子场景引用

## 交付内容

- 新增项目级 `api_automation_reusable_step` 与修订表，并使用 Flyway `V25` 管理。公共步骤名称、说明、基础步骤和版本均受项目作用域与乐观锁保护。
- 场景编排新增 `REUSABLE_STEP` 与 `SUB_SCENARIO` 节点。两类节点只保存来源 ULID 和显式版本，不会引用“最新版本”。
- 控制面在保存场景时校验来源项目、版本和展开后的流程；执行时再次以已固定来源版本展平，并将展平后的基础步骤冻结进执行清单与 Runner runtime artifact。
- 引用展开只接受受限 HTTP Runner 支持的基础步骤；禁止嵌套公共步骤/子场景、子场景自身引用、子场景脚本以及展开后超过 300 个步骤，避免跨项目、递归和任意执行图。
- 子场景复用父场景的环境、变量和失败策略；子场景自身的变量、环境、失败策略和脚本不会隐式注入父场景。
- 接口自动化页新增公共步骤资产区、从选中基础步骤创建公共步骤、公共步骤引用和子场景引用配置。引用节点会展示固定来源版本与执行边界。

## 验证

- 新增 `ApiAutomationScenarioReuseFlowTests`，覆盖公共步骤与子场景的同项目版本绑定、执行清单展平，以及嵌套引用拒绝。
- 后端完整测试：`./mvnw -q -pl services/platform-api test`。
- 前端：`npx pnpm@10.13.1 lint && npx pnpm@10.13.1 test && npx pnpm@10.13.1 build`。
- 本地 MySQL 8.4 已执行 Flyway `V25`。

## 使用路径

1. 在场景画布中选中一个基础步骤，点击“将选中基础步骤保存为公共步骤”。
2. 保存后，在步骤面板添加“公共步骤”并选择该资产；系统写入其当前版本。
3. 添加“子场景”并选择一个无脚本、无引用节点的项目内场景；系统同样写入固定版本。
4. 保存父场景并提交执行。执行清单仅显示展开后的基础步骤，Runner 不会收到引用节点或来源中的可执行脚本。
