# 阶段 4.3.2.2：规则 Mock 报告

## 交付范围

- 同一服务、HTTP 方法和路径可以配置多条 Mock 规则。
- 每条规则支持 0 至 1000 的优先级；运行时按优先级从高到低匹配，同优先级按创建顺序稳定匹配。
- 支持查询参数和请求头的精确条件匹配。
- 请求体支持 `ANY`、`EXACT` 与 `JSON_SUBSET` 三种匹配方式；JSON 子集递归匹配对象字段，数组保持完全一致。
- 管理页新增条件配置区、优先级提示、规则条件摘要和匹配说明。

## 数据与安全边界

- 迁移 `V10__mock_rule_conditions.sql` 放开原有的方法与路径唯一约束，并增加运行时索引。
- 条件字段最多 32 项、单项值最多 8 KB；请求体条件和运行时读取上限为 512 KB。
- 仅执行数据比较，不执行用户脚本、正则表达式或动态模板。
- 未命中任何条件规则仍返回既有的 `404 MOCK_RULE_NOT_FOUND` 响应。

## 验证记录

- `./mvnw -q -pl services/platform-api -Dtest=MockServiceFlowTests test`：通过，覆盖优先级、参数、请求头、精确请求体和 JSON 子集匹配。
- `./mvnw -q -pl services/platform-api test`：通过。
- `npx pnpm@10.13.1 lint && npx pnpm@10.13.1 test && npx pnpm@10.13.1 build`：通过。
- 浏览器验收：在 `/mock` 新建“浏览器验收预览订单”规则，优先级 300，要求 `mode=preview` 与 `X-Client=browser`；列表显示条件摘要。
- 公开地址验收：携带上述查询参数与请求头请求 `/orders`，返回 `200 application/json`。

## 用户预览步骤

1. 打开 `/mock`，选择一个服务后点击“新建规则”。
2. 设置优先级、请求参数条件、请求头条件和请求体匹配方式；配置响应后保存。
3. 调用公开地址时带上对应条件，确认命中高优先级规则；去掉条件时确认回退到低优先级规则或返回 404。
