# 本地加密备份、恢复与升级保护（2026-09-21）

状态：Mac arm64 本阶段通过；独立安装即用整体目标尚未完成。

## 已实现的行为

本地工作区的用户菜单和桌面应用菜单提供“本地备份与恢复”。创建备份需要两次输入至少 12 字符的密码并选择保存位置。数据库及执行进程关闭后，读取数据库版本、汇总文件、加密导出，再自动启动工作区。已有同名备份不会被覆盖。操作期间阻止工作区切换和设置修改；密码输入提交后清空。

恢复先在独立目录验证归档、检查数据库迁移兼容性、准备目标系统密钥，再显示备份时间和文件数量供确认。确认后保留整个原工作区，切换到恢复的数据。错误密码、损坏文件或取消确认不影响当前工作区。当前数据库无法启动时，启动失败页面也提供恢复入口；这一分支已用实际损坏的测试数据库验收。

恢复后的本地身份、业务记录、执行历史与附件保持不变。会话、安全临时状态、任务队列及 Runner 心跳清空；未完成执行标记为取消；定时计划、Webhook 停用；待发通知与未完成报告任务标记失败，避免恢复时重放。原本已成功的历史记录保留。执行目标授权需要重新设置。

后端二进制变化或已有数据库缺少版本记录时，启动前创建冷快照，保留数据库、对象文件、系统加密密钥文件和上一版本记录。快照完整并写入恢复记录后才启动后端。后端与 Runner 就绪后记录新的二进制摘要。同一版本重复启动不重复快照。启动失败时先关闭子进程，再恢复快照；升级中断后下次启动恢复原数据。失败候选目录保留，快照不会自动清理。

## 数据格式及边界

- `.testhub-backup` v1：AES-256-GCM；随机盐和随机 IV；scrypt 参数 N=32768、r=8、p=1。头部也受认证保护，每个数据文件另外记录 SHA-256。
- 归档包含 `workspace.mv.db`、`objects/**`、数据库密码和业务加密密钥。所有这些内容在导出文件内整体加密。原系统的 `workspace-secrets.enc` 不直接导出；恢复时用目标系统安全存储重新加密，重新生成 Runner 心跳密钥。
- 不包含组件缓存、运行日志、执行临时目录、在线服务设置及目标授权。加密备份不能替代账号同步。
- 上限 64 GiB、100000 个文件、16 MiB 清单。拒绝符号链接、目录穿越、重复及常见跨平台不兼容文件名；完整解密验证通过前不启用候选目录。
- 导出使用临时加密文件及排他复制，正常失败不覆盖旧备份。中断时若留下不完整输出，恢复校验会拒绝它；不宣称任意移动文件系统上的发布具备原子性。
- 升级快照是受本机目录权限保护的原始工作区副本，并非可跨机器使用的密码加密归档。业务数据库本身的静态加密策略未在此阶段改变。
- 无签名、无可信来源的备份不应视作不可信 H2 数据库的沙箱；本阶段校验版本、归档完整性和路径边界，未建立恶意数据库隔离执行环境。
- 完整旧工作区保留为 `workspace-before-restore-*`；恢复启动失败的候选保留为 `workspace-unconfirmed-*`。升级快照为 `workspace-before-upgrade-*`；升级失败候选为 `workspace-failed-upgrade-*`。

冷备份遵循 [H2 Backup 文档](https://h2database.com/javadoc/org/h2/tools/Backup.html)的关闭数据库要求；兼容性使用 [Flyway Validate](https://documentation.red-gate.com/flyway/reference/commands/validate) 检查，不修改已经发布的迁移文件。
