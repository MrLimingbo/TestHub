# 桌面本地接口自动化目标授权

日期：2026-09-18，接续 [桌面生命周期验证](desktop-standalone-progress-2026-09-18-lifecycle.md)。改动未提交；整体安装即用改造仍在进行。

## 本轮完成

桌面菜单和本地用户菜单新增“本地执行设置”。用户填写目标 Origin（协议、主机、端口），保存后自动重启本地工作区并启用 API 执行进程，不需要设置环境变量。允许明确授权的本机、内网及在线目标；清空列表即关闭执行。界面明确说明重启会中断正在执行的任务。

- `local-execution.cjs` 校验并原子保存最多 50 个精确目标，拒绝凭据、路径、查询、片段和通配符。配置独立于线上服务地址，损坏配置会报错。无授权是新安装默认状态。
- 只有原生设置窗口主 frame 可以保存授权；在线网页和本地业务网页均不能直接扩大权限。原生层串行处理保存及启动，避免重复启动同一个数据目录。
- 本地启动器将已授权目标传给 Runner，同时设置专门的内网执行开关。该开关需要配置本地队列及凭据；原企业模式默认仍执行公网网络边界检查。
- 每个请求仍须精确匹配目标列表；DNS 解析后固定目标地址，请求不自动跟随重定向。补齐企业模式对 IPv4-mapped IPv6、IPv6 未指定/链路本地地址的拒绝，避免通过地址表示绕过原边界。
- API 执行仍通过原来的签名心跳、租约、运行配置、消息队列和报告持久化链路完成，没有改成浏览器直接伪造执行结果。

真实流程在全新的应用数据目录执行：

1. 首次启动 Runner 心跳可信，但执行开关关闭。
2. 在原生设置中提交非法路径，提示错误且不重启、不改变授权。
3. 填写临时回环 HTTP 服务 Origin，应用重启后身份不变、执行开启。
4. 创建真实接口场景并执行到 **SUCCEEDED**，HTTP 服务收到请求。
5. 执行未授权的另一目标，任务未成功且服务收到 **0 次请求**。
6. 关闭并重新打开 App，原授权和场景仍在，再次执行成功。
7. 清空授权并重启，执行再次关闭，原场景不能继续产生 HTTP 请求。

允许目标合计收到 2 次请求；未授权目标为 0 次。服务和应用均在测试结束后关闭，未触碰用户已有 TestHub 数据或安装程序。本轮后端 Java 未修改，沿用上一阶段两种模式各 171/171 的回归证据；没有将其称为本轮重新执行结果。
