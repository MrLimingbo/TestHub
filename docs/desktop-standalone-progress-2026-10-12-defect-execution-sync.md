# TestHub 安装即用：缺陷执行用例关联双向同步

日期：2026-10-12。上一模块“缺陷负责人／抄送同步”已获用户审核通过。本轮依据用户确认的“绑定时逐一确认执行批次，再按用例编号匹配”实施关联同步。实现、最终源码／内部包验证及阶段清理已完成，已于 2026-10-12 获用户审核通过。

## 使用与边界

桌面缺陷页和应用菜单新增“缺陷执行关联同步”。连接账号服务并登录，选择两端项目、读取已有执行批次，逐一确认一对一对应关系，再预览并确认绑定。计划编号须一致；页面显示计划编号、批次名称、实际批次标识末八位、状态、开始时间及用例范围，选择后另显示完整描述。同名批次不自动选择，不按名称或时间推断。每个已选批次内按不可变用例编号匹配已有执行用例。

仅同步已有缺陷的完整 `RUN_CASE` 关联集合，支持主动清空；不创建缺陷、批次或执行用例。需求／测试用例关联、缺陷内容、人员、工作流和全部执行结果、步骤、备注、时间、操作人保留各端。执行历史本身的持续同步单独验收。当前历史与计划／用例定义须先存在于两端，可由原有执行功能准备；本模块不会用复制历史代替关联映射。

已确认的源执行用例 ID 映射为实际目标 ID，提交只发送目标引用。保留既有关联的 ID、创建时间与操作人，删除移出的执行关联，新增关联由目标实际同步账号创建；其他关联不变。相同集合不重写业务记录。显式启用后应用运行时每 30 秒检查，可立即同步、暂停／恢复或解除绑定。

首次集合不同、双端修改需选择完整集合，不自动合并。冲突页显示计划／批次／用例标签，保持键盘焦点；确认期间内容或实际缺陷 ID 变化时拒绝旧选择。未配对批次、所选批次内用例缺失、历史重建、计划／用例实际对象变化、已有失效关联阻断涉及的缺陷，不从其他同名批次补引用，不将引用失效当作主动清空。当前和基线依赖共同检查，其他有效缺陷仍可同步。缺陷缺失不自动创建或删除，同编号重建且集合不同时须重新审核。更改配对须解除绑定再预览，不删两端业务数据。

## 协议与保护

新增 `GET/POST /api/v1/projects/{projectId}/functional/defect-execution/sync`，协议 `FUNCTIONAL_DEFECT_EXECUTION_SYNC` / 1。定义仅包含排序去重的 `runCaseIds`；快照包含实际缺陷标识、项目内已有执行引用的最小身份／批次显示信息和失效标记，不读取其他项目、执行正文、备注或操作人。

每项目最多 100 条缺陷、1000 条执行用例、10000 条执行关联；每缺陷最多 100 个引用，合并含缺失基线最多 100 条，快照／合并最多 3 MiB，请求／响应最多 4 MiB。超限拒绝，不裁剪。

H2 V35／MySQL V92 仅新增持久回执，旧迁移不改。快照 REPEATABLE READ，写入 READ COMMITTED；与原有缺陷关联操作及计划／用例操作共享项目锁，锁后重新读取版本。版本包括实际缺陷、关联 ID／引用／归因／时间、执行引用的批次／计划／用例实际 ID 及编号；执行结果、备注、批次显示名及状态不作为引用身份。全批预校验，专用服务只增减 RUN_CASE 关联，业务写入、审计和回执同事务；失败回滚。

待提交请求在本机 OS 加密文件 `functional-defect-execution-sync.bin` 原子保存，权限 0600，包含目标原始引用和请求标识。响应丢失后应用／账号 JVM 重启重放原回执及提交时实际对象 ID，不覆盖之后的手动修改。账号／服务切换、CSRF、角色／项目边界、磁盘失败、负载及不可信 IPC 帧受保护。远程页面只能打开原生工具；读取配对和提交仅可信原生页面调用。十六类绑定独立共存，恢复备份后全部持久暂停并要求重新预览。
