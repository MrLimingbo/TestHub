# 第二批 P2：8 项观察复现与修复对照

范围：用户批准的六组 A 规则。以下“修复前”基于本轮保存的源文件基线及受控数据复现；不要求修改用户工作区、真实插件或外部通知。测试账号、令牌、请求头和正文均为隔离夹具。

## OBS-13-E014：任务行操作在切项目后继续提交（D20）

前置：项目 A、B 各有可操作的 QUEUED 手工任务；可在测试代理中延迟 `/api/v1/auth/csrf` 响应。

1. 登录并选择项目 A，打开“任务”。
2. 延迟 CSRF 响应，点击某任务“标记执行中”。
3. CSRF 尚未返回时切换到项目 B；也测试 A→B→A。
4. 放行原 CSRF 请求，观察业务请求和当前页面。

修复前：原行操作仍会发出 PUT，切换回来也可能接受旧结果。预期：业务请求尚未发出时取消；已经发出的 PUT 仍归原项目，不补发撤销请求。

修复：操作绑定项目、页面代次、登录代次；CSRF 后再次判断；每次操作使用独立令牌，迟到的 finally 不清理新操作。用例 `TC-P2R2-D20-01/04/05/06/07/08`。

## OBS-14-E022：通知行操作切项目后仍提交（D20）

前置：项目 A 有 FAILED 投递及可删除模板；代理可延迟 CSRF。

1. 打开“通知、集成”，选择项目 A。
2. 对失败投递点击重试并确认，延迟该操作的 CSRF；删除模板执行同类检查。
3. 切换项目 B，再放行原 CSRF。
4. 检查重试/删除的业务 HTTP 请求，以及新项目列表和 loading。

修复前：新页面虽可能忽略迟到结果，原业务写入仍会发生。预期：提交前视图/项目失效即取消，已提交请求保持原范围。

修复：把行操作有效性回调传入提交函数，使用独立令牌和同步失效监听。用例 `TC-P2R2-D20-02/04/07`，并保留原通知表单回归。

## OBS-14-E023：全局插件离页后仍可提交（D20）

前置：隔离夹具中存在可启用插件，不操作用户真实插件。

1. 打开全局“插件”页，点击启用并确认声明权限。
2. 延迟 CSRF，导航离开插件页面，再放行响应。
3. 检查插件业务请求是否发出。
4. 对照：留在插件页，只切换顶栏项目，再完成同一流程。

修复前：离页后仍可能发出启用请求。预期：离页或登录失效取消未提交操作；仅切项目不取消仍有效的全局操作。

修复：按全局页面与登录代次保护，不错误绑定项目；迟到响应不更新新页面。用例 `TC-P2R2-D20-03/04/06/08`。

## OBS-07-U012：脱敏旧摘要借用现有请求配置直接发送（D13）

前置：旧历史只有 Method/URL，URL 含 `token=***`；另有已配置认证、Header、Body 的请求。有效加密历史和 P1 已过期/未知创建时间/不可读历史作为对照。

1. 先配置另一个请求的认证、Header、Body。
2. 从旧历史载入仅有 Method/URL 的摘要；嵌入式快捷请求入口同样执行。
3. 不重建、不核对，点击发送或历史重放。
4. 勾选核对但保留脱敏字段，再次尝试；然后补齐字段并手动发送。
5. 对照测试新建请求中的普通字面量 `***`、有效加密回放，以及 P1 不可回放历史。

修复前：旧摘要可能借用无关配置，实际发送脱敏占位内容；不同入口的拦截不一致。预期：清空无关配置、明确旧摘要来源，重建核对后才可手动发送；加载不发请求；不全局禁止普通 `***`。

修复：贯通旧来源标记与作用域、统一发送校验；无效加密回放不回退借用当前请求。现版本确有历史重放按钮，本轮按实际入口测试。用例 `TC-P2R2-D13-01` 至 `08`。

## OBS-07-E012：WebSocket 草稿与旧连接失配（D14）

前置：本页已有连接 A；准备 URL、Header、认证或订阅配置不同的历史/草稿 B。

1. 在当前页面建立 A。
2. 只读载入 B，或编辑连接配置。
3. 尝试发送文本消息，记录是否仍送入 A。
4. 显式点击连接 B，记录 A 的 close 与 B 的 connect 顺序。
5. 将 A 的 close 改为受控失败，再尝试替换。
6. 另测 connect 响应迟到前切项目/离页；检查只清理原项目、原连接 ID。

修复前：草稿与活动连接可能失配，替换流程不能保证只保留一个本页会话。预期：只读载入不自动关闭/连接/订阅；配置不匹配禁止发送；显式替换先确认自有旧连接到终态，关闭失败保留句柄并阻止新连接。

修复：加入本页会话所有权管理、配置比对、顺序替换及迟到创建清理。手动关闭停止重连，不关闭其他页面/账号/项目的连接。用例 `TC-P2R2-D14-01` 至 `08`。受控浏览器会话 RPC 不等同于真实远端 WS 服务验收，也不是升级退出复验。

## OBS-07-F012：正式接口高级调试丢认证且敏感草稿落 Web Storage（D15）

前置：同一登录会话、项目、窗口；源接口配置运行时认证、Header、Body。

1. 打开正式接口“调试”，配置 Bearer；分别对照 NONE、Basic、API Key Header/Query。
2. 点击“高级调试”，检查地址栏及 localStorage/sessionStorage。
3. 目标页面加载后先不操作，确认无自动执行或历史写入。
4. 手动发送，逐字段比较 method、URL、Header、Body、环境与认证。
5. 对照整页刷新、重复消费、项目 A→B→A、退出重登、其他窗口、错误源接口 ID 和不支持认证模式。

修复前：交接未完整保留运行时认证；使用 Web Storage 保存含请求头/正文的交接草稿。预期：完整请求只保存在当前会话的一次性内存中；URL 只有随机标识和源接口 ID；失效后空白并提示，不借用其他认证。

修复：单包内存交接，校验登录/项目/来源，消费一次；保留原始请求字段至用户对应编辑，避免编辑器自动添加 Header 改变请求；失效后清空。旧草稿存储契约及旧密文不批量删除。用例 `TC-P2R2-D15-01` 至 `08`。

## OBS-03C-E005：审计动作下拉随行筛选收缩（D04）

前置：系统管理员；至少两种动作 A、B；另有一种旧动作在最新 200 行之外。

1. 打开“权限与审计”，展开动作下拉。
2. 选择 A，再展开，尝试直接选择 B。
3. 检查旧稀有动作能否被选到；查询不存在的动作得到空行后再次检查。
4. 对照普通账号、匿名、可选项目范围；模拟元数据失败及 401/403。

修复前：选项从当前返回的行计算，筛选 A 后其他动作消失，超出行数上限的动作不可达。预期：独立动作元数据，沿用管理员及项目边界，不被 action/limit 收缩；行数限制不扩大。

修复：新增 `/api/v1/audit-logs/actions`，数据库 DISTINCT/排序；页面独立读取，失败标旧、权限丢失清空缓存。用例 `TC-P2R2-D04-01` 至 `06`。真实 JAR/HTTP、两种数据库和实际 Arco 下拉分别验证。

## OBS-11-E022：页面对象冻结说明与实际时点冲突（D18）

前置：场景引用一个启用页面对象；定位器先为 A。

1. 保存场景，查看“页面对象”说明中的冻结时点。
2. 在执行入队前将对象定位器改为 B，执行并读取清单。
3. 已入队后改为 C，再读取原清单；再触发新的执行/重试/定时入队。
4. 对照直接定位器及缺失、跨项目、停用引用，检查失败时无部分清单/执行残留。

修复前：页面说保存场景即冻结，实际为入队解析并冻结。预期：保留已有入队行为，新入队/重试读取当时有效配置，旧清单不变。

修复：更正说明及“已保存步骤”标题；不改变后端冻结时点，不回填旧清单。本组后端首次验证即通过；原说明在修复前专项中失败。用例 `TC-P2R2-D18-01` 至 `07`，不声明真实 Runner 或设备执行已覆盖。
