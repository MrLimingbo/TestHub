# 八项观察的复现与修复验收

本文件保留修复前复现方法；最终执行结果见同目录 `FINAL-REPORT.md`。所有操作仅使用新建的隔离 QA 项目。修复授权为六组 A 规则，覆盖八项观察；这些是观察项整改，不改写已审核的历史 Bug 数量。

## OBS-03B-E001 / D01：未定义环境仍能写入配置

前置：有项目配置写权限；项目不存在环境编码 `{未定义环境}`。

1. 读取该项目环境列表，确认不含该编码。
2. 向 `POST /api/v1/projects/{项目ID}/parameters` 提交该编码、合法参数名和值。
3. 再向同项目 `/secrets` 提交该编码、另一合法密钥名和值。
4. 查看参数表、密钥表与成功审计记录。

修复前：上述请求会落库，产生没有环境定义的配置。修复后：两类请求均 400，拒绝发生在加密和写入前，无新配置及成功审计。通过直接 SQL 构造的旧孤立行仅用于兼容验收：仍可见、标记缺失定义、禁止编辑；不自动补环境、迁移或删除。另验证项目隔离、原归一化、与环境删除并发时不会新增孤立记录。

用例：`TC-P2-D01-01` 至 `10`；服务端 `P2EnvironmentRulesFlowTests`、组件 `p2EnvironmentUi.test.ts`、无窗口浏览器和真实 HTTP 补证。

## OBS-03B-E005 / D03-CFG：停用环境配置维护的 UI/API 不一致

前置：定义一个停用环境，操作者具有配置写权限。

1. 打开“项目设置 → 环境参数”，点击“新建参数”或“新建密钥”。
2. 尝试在环境下拉框选择已停用环境。
3. 对比直接调用同项目参数/密钥保存接口的行为。
4. 尝试执行使用该环境的自动化场景。

修复前：API 允许维护，界面却禁止选择该环境。修复后：界面与 API 均允许维护，标记“已停用（不可执行）”；停用不等于定义缺失。原 P1 执行 409、Quartz 跳过、已接收执行快照保持等规则不变。

用例：`TC-P2-D03-CFG-01` 至 `06`；另复跑 P1 停用环境保护。

## OBS-06-E006 / D09：导出响应码丢失或非法值被宽松转换

前置：创建含单响应元数据的接口版本，保存合法状态码 201（以及正式矩阵中的其他合法码）。

1. 分别导出 OpenAPI、Postman、HAR，读取各格式的响应状态字段。
2. 在独立 QA 数据库中准备当前版本的非法元数据：浮点 JSON 数字、范围外值、非数字字符串或非空损坏结构。
3. 再分别导出，检查 HTTP 状态及下载内容。
4. 用含单一 201 响应的 OpenAPI 导入后导出，对比状态与正文。

修复前：OpenAPI/Postman 可被固定为 200；HAR 对浮点值等存在宽松转换。修复后：三格式保留 100–599 的合法整数，兼容首尾空白十进制数字串；缺失/null/空元数据默认 200；浮点（包括 200.0）、非法字符串、越界和损坏元数据均受控 400，无导出文件。单响应导入导出保持一致；未引入多响应模型，未重写旧版本。

用例：`TC-P2-D09-01` 至 `13`；三格式 × 八个状态码共 24 个数据组合属于这些用例的执行数据，不额外计为 24 条正式用例。

## OBS-06-E012 / D10：浏览器递归复制留下部分资产，重试重复建分支

前置：同项目父目录下有源目录、子目录和两个接口；至少一个接口有多个版本。

1. 对源目录执行复制；在较早接口已写入后，让后续写入发生受控数据库失败。
2. 检查目录、接口、版本、成功审计和复制回执。
3. 再验证所有资产写完、回执插入失败的场景。
4. 成功提交后模拟响应丢失，以同一 UUID 请求 Key 和预检摘要重试；并发重试，再重启真实 QA JAR 后重试。
5. 用同一 Key 改变载荷；用新 Key 明确复制第二份；在预检后修改源树再提交。
6. 分别准备合计 200 和 201 项（目录＋接口，含根目录）的源树；保留一个既有部分副本分支。

修复前：界面逐项提交，后续失败会保留早先写入，整轮重试再建副本。修复后：服务端同项目同父级一事务复制，只复制当前版本，自动避让命名和路径冲突；资产、审计和持久回执同时提交/回滚。200 项成功、201 项 400 且零写入；源快照变化 409。同 Key 同载荷返回原回执，同 Key 不同载荷 409，新 Key 可明确新增一份。界面在不明确的网络错误后保留原 Key/摘要，并阻止项目切换后的误提交和迟到刷新。旧部分分支不清理。

用例：`TC-P2-D10-01` 至 `13`；故障通过隔离测试注入，无生产故障开关。真实 JAR 重启补证独立记录，不视为升级关闭超时复验。

## OBS-10-E010 / D17：性能测试查询键 trim 后覆盖

1. 创建合法压测计划，在同一线程组 `queryParameters` 同时提交 `key` 和 ` key ` 两个原始键。
2. 分别使用相同值、不同值、反向插入顺序重试。
3. 对已有计划执行相同非法编辑，核对原计划、线程组、版本与审计。

修复前：归一化后后值覆盖先值。修复后：覆盖前返回 400，整项创建/修改不落库。不同线程组/对象可各自使用同名键，原大小写规则保留。

用例：`TC-P2-D17-01/04/05/06/07/08/10`。普通 URL 中重复查询参数通过既有 cURL 导入链路验证合法性；压测目标 URL 本来禁止直接带 query，该既有规则不改变。

## OBS-11-E020 / D17：Web UI 变量键 trim 后覆盖

1. 创建有效浏览器配置与合法 WAIT 场景。
2. 在同一 `variables` 对象提交 `key` 和 ` key `；重复相同值、不同值、反向顺序。
3. 核对没有产生覆盖后的场景；合法不同对象和大小写输入仍按原规则处理。

修复前：后一个归一化变量静默覆盖前一个。修复后：写入前 400；字段本身的合法性和权限校验保持。

用例：`TC-P2-D17-02/04/05/06/07/08`，与性能、适配器共用的正式用例按 ID 去重计数。

## OBS-14-E025 / D17：企业适配器配置键 trim 后覆盖

前置：系统管理员；合法企业微信或 OIDC 配置，仅用合成测试值。

1. 在同一 `configuration` 对象提交 `webhookKey` 和 ` webhookKey `。
2. 验证新建及编辑、相同值/不同值、反向顺序。
3. 保存一份合法配置，记住其密文字节；提交上述冲突编辑，核对原配置、密文与成功审计。
4. 再提交省略 `configuration` 的合法元信息编辑。

修复前：冲突覆盖后被加密保存。修复后：加密和持久化前 400；失败不改密文或原行。省略配置的合法编辑继续保持原密文字节；非管理员仍被拒绝。不恢复历史上已覆盖的值；不处理完全同名 JSON 原始属性、其他数值转换或未知字段规则。

用例：`TC-P2-D17-03/04/06/07/08/09`。

## OBS-13-E020 / D22：定时质量报告编辑缺少版本前置条件

前置：创建计划，两名有权编辑的客户端均读取相同版本（新计划为 0）。

1. A 携带 `expectedVersion: 0` 更新名称/Cron/项目范围。
2. B 使用旧值 0 提交另一份草稿，检查数据库、调度与审计。
3. 分别省略版本、传 null、负数、小数、字符串及其他非法类型。
4. 两客户端同时提交同一版本，统计成功数。
5. 在界面触发冲突，确认草稿保留；主动点击“读取最新版本”，对比展示的最新配置，再明确点击保存。
6. 执行一次计划，仅更新运行记录后，用原配置版本再次编辑。

修复前：更新不要求版本，两份草稿可能依次覆盖。修复后：复用现有 `config_version`，对外返回 `version`；合法版本含 0，可原子更新并递增一次。同版本并发只有一方成功，另一方 409；缺失/null 428，非法类型/范围 400，不改配置或成功审计。界面无自动合并或自动重试；运行元数据不增加配置版本。原同步 revision、权限、删除和执行语义保持；不承诺新增数据库与 Quartz 的跨资源事务。

用例：`TC-P2-D22-01` 至 `11`；另复跑既有质量报告同步套件。
