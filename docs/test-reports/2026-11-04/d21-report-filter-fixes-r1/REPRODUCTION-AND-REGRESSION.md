# D21 复现步骤与回归对照

范围：OBS-13-E019 / D21-A，质量报告项目筛选严格显式列表。下列为同一观察的三种失败切面，不计为三个新增产品Bug；只使用隔离QA账号和项目。

## 1. 显式空键回退到默认范围

1. 在隔离库创建有两个可访问项目的用户，登录，确认两个项目在可访问上下文中。
2. 发出原始URL：`GET /api/v1/reports/quality?from=2026-11-04&to=2026-11-04&projectIds`。另覆盖`projectIds=`及URL编码的空格/制表符。
3. 已批准预期：显式提供空参数返回400，不能转换成默认全部项目；只有省略整个参数才使用默认范围。
4. 有效修复前红测B02在第一个无等号空键断言处实际200、期望400。Spring的List绑定使该值成为空列表，服务据此选择默认全部。该断言后的同方法变体在红测中未继续执行，不推定其结果。
5. 修复后B02所有输入分别经过真实本地HTTP查询与导出，均返回400，无项目数据、无CSV响应及成功导出审计。

## 2. 重复键中的纯逗号被丢弃

1. 使用上述隔离登录会话，取一个合法可访问项目ID记为`{A}`。
2. 发出原始URL：`GET /api/v1/reports/quality?projectIds={A}&projectIds=%2C`。
3. 预期400，因为第二个显式列表有空段；不能丢弃该值后仅统计A。
4. 有效红测B03实际200、期望400。只使用单个`projectIds=%2C`原来已返回400；触发点是重复键使CSV进入服务层后默认split丢掉全部空段。
5. 修复后单逗号、连续逗号及其与合法重复键的组合，在查询与导出均400，导出成功审计不变。

## 3. 重复键中的CSV尾空段被丢弃

1. 取两个合法可访问项目ID记为A和B。
2. 发出原始URL：`GET /api/v1/reports/quality?projectIds={A}%2C&projectIds={B}`。
3. 预期400；第一个值结尾有空CSV段，即使另一个键合法也不能容错忽略。
4. 有效红测B04实际200、期望400。单键`projectIds={A}%2C`在原HTTP绑定路径已400，不能仅凭服务层split推断所有原始URL都失败。
5. 修复后头/尾/连续逗号、空白中段及与重复键混合的输入，在查询和CSV导出都400。

## 回归边界

- 后端13个方法使用真实随机端口HTTP及独立Cookie登录，覆盖两个端点；不是只用MockMvc.param模拟列表。
- 合法单ID、多ID、CSV、重复query键及混合形式按trim、首次出现顺序去重；去重后50个允许、51个400。51个token但只有50个唯一ID仍允许。
- 省略参数保留默认全部可访问范围，即使默认集合超过50也不新增上限。
- 跨组织或同组织未授权项目仍403，不能退回其他可访问项目；拒绝时无项目数据或成功导出审计。合法导出仅给实际纳入项目记录原有审计。
- 前端4项验证初始全选显式范围、清空省略参数的说明、超过50时空选择防错以及50/51显式选择限制。原页面无需生产修改。

完整有效红测13项中10通过、3失败、0错误/跳过，保存在[修复前摘要](BEFORE-RESULTS.json)。失败首先发生在查询状态断言，后续导出或输入变体当时未执行；最终通过记录另行保存在回归结果中。

测试维护：首次组件运行2通过/2失败，原因是夹具按组件根节点aria-label寻找Select，但该属性由Arco转交内部输入；已改为在统计筛选容器中查找Select，原断言未放宽，随后4/4通过。它不是产品Bug或新增历史正式测试资产问题。
