## 新增待审Bug：重复登记同类型同名适配器返回500

编号BUG-D23-001，P3，状态OPEN_PENDING_RULE_REVIEW。**尚未修复；D23-A本批兼容结论与该问题分列。**

前置条件：自有隔离库中的系统管理员；启用正常会话与CSRF。只登记配置，不需要连接真实OIDC服务。测试夹具事务回滚，不改变用户实际适配器或信任密钥。

1. POST `/api/v1/extensions/adapters`，使用新的displayName和adapterType=`OIDC`，endpoint为合法测试HTTPS地址；configuration提供合法clientId、clientSecret、redirectUri，enabled=false。
2. 第一次返回200，适配器成功登记。
3. 原样重复第1步请求，不附加未知字段。
4. 实际返回500，公共错误为INTERNAL_ERROR；服务触发`uk_enterprise_adapter_name (adapter_type, display_name)`唯一约束，对应DuplicateKeyException。
5. 在同一请求中附加`"d23Unknown":"D23_UNKNOWN_SENTINEL"`后再重复，仍返回500。
6. 独立X01采集确认两种请求均无业务行、角色、信任、回执或成功审计变化。它们的500不是X01应通过的验收结果，采集方法成功只证明证据已获取。

影响：管理员重复提交同类型同名配置时得到服务器内部错误，缺少可操作的冲突提示。未知字段策略没有改变该行为。

建议：另案对创建和更新的名称冲突给出受控错误，推荐409并提示同类型名称已存在；明确是否允许原记录保留原名，覆盖并发重名和无部分写入。最终返回码及扩展修复范围待用户审核，当前不把未经确认的409/400规格写成正式通过判据。此新发现单独登记，不加入47项历史观察或108个历史已修复Bug。

## D23回归边界

- 仅4类DTO、6个写入口。普通创建/更新附加未知标量/对象/数组，与合法基线投影相同；不入库、不生效，不把附加主体/角色字段当授权。
- 拼错、缺失/null/空白必填字段，错误对象/数组类型及渠道、适配器类型、公钥、清单权限等已知业务规则继续拒绝。缺失登录或CSRF、普通用户扩展写、项目只读用户通知写继续拒绝，无成功审计或行变化。
- 合法动态configuration自定义键保留且加密，公开响应仍脱敏；错误Map结构或缺少必填配置仍拒绝，更新null保留密文。
- 包登记/升级仍按原签名、版本和默认停用规则；manifest原始首尾空白参与签名及checksum，已知内层内容保持。数据库JSON可能规范化排版，不宣称逐字节归档，也不新增任意内层未知字段政策。
- 通知迁移/同步的顶层和嵌套DTO未知字段均拒绝，无模板/回执/成功审计写入。全局ObjectMapper、严格reader及PluginManifest未改动。

本轮不处理D26基线，不补齐12项环境；升级关闭超时仍独立未确认，未调查或复验。
