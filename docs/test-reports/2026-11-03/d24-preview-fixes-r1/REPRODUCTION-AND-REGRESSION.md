# D24 详细复现与回归对照

对应OBS-15-E001一项观察，不把多个失败断言计为多个新Bug。仅在自有测试工作区使用受控服务。

## 原问题操作路径

1. 从桌面账号工作区打开“功能测试资料同步”等原生同步页面。
2. 让项目context或同步预览的只读GET保持等待，例如受控服务暂不返回项目列表或快照。
3. 尝试取消或关闭原生工作区窗口。
4. 原实现没有操作级取消入口/信号传播；context/preview持有迁移互斥，窗口关闭被阻止，只能等读取或既有请求超时。一次性迁移的context/prepare也使用同类锁生命周期。

原窗口行为由历史OBS-15-E001及源码复核承接。本轮保留两个修复前Node红测：N10向syncRequest传入signal后取消，底层实际signal.aborted仍false；N13注入共享读取生命周期后context调用次数实际0、期望1。2个均失败，0个通过。没有在旧实现上补造24项红测或真实离屏红测。

## 修复后的协作式取消

1. 打开同一页面，让context/preview或迁移prepare处于受控只读等待。
2. 点击“取消预览”，或请求关闭此窗口。
3. 页面立即提示正在取消；本操作plan立即失效，传输signal收到abort。
4. 等待真实请求/读流结束；只有原exclusive已执行finally释放本操作锁后，才发布取消终态并允许关闭。
5. 再用旧token尝试绑定/提交，应拒绝；重新预览可得到独立新token。

## 不可立即中断及竞争边界

1. 让一个本地只读步骤忽略取消并持续6.5秒，取消后继续观察。
2. 超过5秒应显示终止未确认，锁仍持有，写操作不能并发进入，窗口不能提前关闭。
3. 实际步骤结束后才释放锁并关闭；不强杀进程、不伪造5秒内终止。
4. 令取消与正常成功竞争，应只落一个终态。重复取消同一操作幂等；旧ID、外窗口、子框架和错误页面不能取消新操作。
5. 令取消后的旧结果迟到并尝试新建plan，应再次丢弃；另一个窗口的草稿及新预览不被覆盖。

## 本轮验证边界和测试维护

Node覆盖全部34组同步与11组迁移入口；真实离屏Electron采用生产协调器、IPC、preload及功能同步页面代表性夹具，不声称45个页面均做了真实端到端连接。详细计时以native-results.json最终成功运行记录为准。

测试维护单列：API迁移旧VM夹具补入新的读取包装函数，保留原认证、主框架、锁和默认取消断言；Vue夹具改用磁盘路径读取原生脚本，修复happy-dom中非file URL准备错误；Node矩阵补齐legacy transfer客户端引用；首次离屏夹具误点旧轮询ID，已改为等待当前操作ID并手工释放迟到步骤。完整桌面首轮7项因sandbox禁止loopback绑定而EPERM，使用授权隔离loopback后按原断言重跑。上述不记为新增产品Bug或历史正式测试资产问题。
