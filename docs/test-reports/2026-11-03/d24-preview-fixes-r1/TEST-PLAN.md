# D24 原生预览取消：先行用例

依据D24-A、OBS-15-E001及已批准AC01–05。先冻结本计划、入口清单和源码基线，再进行红测、最小修复及后台回归。入口数量以[完整清单](ENTRY-INVENTORY.json)为准，覆盖公共同步context/preview和迁移context/prepare。打开页面前既有登录/运行时预检不作为预览；写操作、上传、备份恢复及应用整体退出沿用原锁和确认。

24个场景：正例13、反例8、混合3；Node17、渲染夹具3、离屏Electron4。入口和输入变体不增加场景数。下列是设计预期，不是通过记录。

|ID|类型|操作与预期|
|---|---|---|
|N01|正|context受控请求取消，终止确认后释放自有锁；无业务写入。|
|N02|正|preview协作取消，操作信号传播；失效预览不可绑定。|
|N03|反|忽略取消的本地步骤超过5秒仍等待，锁定且拒绝并发写入；实际结束后释放。|
|N04|反|取消后迟到结果不能返回可用token或留下plan；下一次预览独立。|
|N05|混合|取消/成功竞争只产生一个终态，成功赢时正常token可用，取消赢时拒绝。|
|N06|正|重复取消同一操作幂等，不取消后续操作。|
|N07|反|外窗口、子框架、错误页面及旧操作ID不能取消当前操作。|
|N08|正|正常context/preview完成，锁释放，预览及后续原确认流程可用。|
|N09|混合|网络失败和超时受控失败，资源/监听器/锁清理，可再次执行。|
|N10|正|JSON读取期间取消，停止读流且释放reader；会话、重定向及大小限制保持。|
|N11|混合|二进制读取取消资源清理；原摘要、大小、空文件限制不放宽。|
|N12|反|写操作不接受预览取消，也不能与取消未确认的预览并发。|
|N13|正|逐个安装全部同步入口，context及自定义preview参数使用同一取消契约和原发送者检查。|
|N14|正|全部迁移context/prepare使用同一契约，取消使对应客户端plan失效；commit保持原确认。|
|N15|反|页面离开或窗口关闭触发取消；未终止前不关闭，不能提前清全局锁。|
|N16|正|无预览操作时传输正常，既有超时/调用者signal仍生效，不影响写请求。|
|N17|正|成功、取消及失败后移除本操作监听器/状态引用，不撤销别的操作资源。|
|U01|正|取消控件可键盘使用，点击立即显示正在取消；终态提示准确。|
|U02|反|旧轮询/离页后的响应不得覆盖新页面或新操作状态。|
|U03|正|只读活动显示取消控件；写操作无可取消入口，原控件保护保持。|
|E01|正|真实离屏Electron中受控读取可取消，反馈实测≤1秒、终止确认及释放≤5秒。|
|E02|正|真实窗口close请求在取消并释放锁后完成关闭，不显示/聚焦窗口。|
|E03|反|真实离屏不可立即中断夹具超过5秒显示终止未确认并继续锁定，结束后才可关闭。|
|E04|反|真实离屏迟到结果/失效token不能绑定；新窗口/新预览状态保持。|

先用Node/VM及受控网络复现无取消传播，再增加操作级AbortController与实际终止确认；不以Promise.race提前结束/隐藏窗口/杀进程代替取消。传输层合并原超时与取消信号，读流清理纳入实际结束。使用同一取消状态机覆盖全部入口，不修改各模块业务同步算法。

离屏验收从启动前设置show:false、focusable:false、offscreen:true及macOS禁止激活，拒绝意外原生对话框；仅使用自有临时数据。会明确区分Node/渲染夹具与真实Electron证据，不声称已验证发行包或安装升级。

实施中入口补充：复核首次页面流程后，将34个未加载status也纳入N13矩阵及同一只读取消契约；已加载status仍只读内存、不占新锁。冷status只准备本地元数据，后端启动置于后续受保护操作中。范围为45组、124个处理器（其中34个status仅冷启动分支），仍为24个场景，不增加用例总数。

定向通过后运行桌面完整Node套件、相关渲染测试和lint；如变更不涉及后端，不重复数据库验收。保留脱敏结果并清理自有进程/临时工作区。12项环境补齐暂缓，升级关闭超时独立未确认，本轮不调查或复验。
