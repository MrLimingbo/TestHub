## D07：PUT不同计划编号仍返回成功

1. 创建编号PLAN-1的计划，包含一个测试用例，记录名称、状态和成员。
2. 向 `PUT /api/v1/projects/{projectId}/functional/plans/{planId}` 提交planCode=OTHER-1，并同时修改名称与caseIds。
3. 修复前B02首个断言实际得到200；原更新代码忽略编号而继续更新其他字段。红测在200断言失败后停止，不冒称后续无副作用断言当时已执行。
4. 修复后返回400，提示planCode创建后不可修改；原计划及关联、成功审计数量不变。
5. 对照：PLAN-1及trim/大小写等价的 ` plan-1 ` 可正常编辑其他字段。缺失、null、空白及非法格式400，页面编号仍只读并发送原编号。

## D08：历史标题跟随源用例改名

1. 创建标题A、步骤A的用例并加入计划，创建执行批次。
2. 将源用例改为标题B、步骤B。
3. 读取旧批次用例列表。修复前B04实际标题跟随为B，期望A而失败；代码通过关联当前源用例读取标题。
4. 修复后旧批次保持标题A、步骤A，titleSource=SNAPSHOT；新批次记录标题B、步骤B。
5. 对照旧记录：模拟缺少标题快照的旧行时，仍显示当前标题B，但titleSource=CURRENT_ASSET且页面提示“旧记录未保存标题快照”；不批量回填。

## 迁移、同步及旧端兼容

1. 将新批次标题快照随执行历史迁移或同步到资产当前标题不同的目标。
2. 目标应保持原快照；旧格式省略titleSnapshot时保留缺失，不拿目标标题伪造历史。
3. 尝试通过已有历史同步改写或移除titleSnapshot：409，不替换历史布局、结果或关联。无效快照400且无部分资料/回执。
4. 带快照的HTTP导出未声明titleSnapshots=true时400，明确要求更新客户端；声明后正常导出。桌面先检查目标historyTitleSnapshots或titleSnapshotsSupported能力，不支持则停止，不发送可能丢失快照的资料。
5. 无标题快照的旧历史保持原版本和序列化形状；不更改执行历史之外的迁移范围。迁移1至8范围版本未增加。
