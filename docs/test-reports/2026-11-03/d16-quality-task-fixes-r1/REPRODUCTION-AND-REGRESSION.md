# D16 质量报告与任务：复现与回归

同属原观察 `OBS-13-E018`；下列为不同触发路径，不重复计为多个历史 Bug。所有复现均应在自有隔离项目和账号中进行。

## 任务更新省略进度导致清零

1. 创建任务，使用合法更新将状态设为 RUNNING、进度设为10，并记录版本。
2. 对 `PUT /api/v1/projects/{projectId}/tasks/{taskId}` 发送合法名称、状态和 `expectedVersion`，但省略 `progress`。
3. 修复前：定向红测复现请求被接受，省略的 primitive 进度被当作0。修复后：返回400，任务值、版本及成功审计不变。显式 `null` 也应拒绝。
4. 提交合法数字 `10.0` 或 `1e1` 应保存为10；提交 `1.5`、`1.0000000000000001`、`"10"`、越界值或容器应返回400。QUEUED 和 SUCCEEDED 也必须先校验非法输入，再对合法输入归一为0/100。

## 任务迁移小数被截断

1. 导出一份含 RUNNING、进度10任务的资料，在原始迁移 JSON 中把该项 `progress` 改为 `1.5`。
2. 向隔离目标项目 `POST /api/v1/projects/{projectId}/tasks/transfer` 提交资料。
3. 修复前：定向红测复现请求被接受。修复后：返回400，不新增任务、迁移回执或成功审计；明确的 `10.0` 和 `1e1` 可作为整数10导入。同步入口同样覆盖缺失、错误类型、边界及后续非法操作导致整批无部分写入。

任务修复前5个方法中2通过、3失败，分别停在缺失 PUT、缺失同步进度和迁移小数被接受；循环在首个断言失败后停止，不能推断剩余输入均已在修复前动态验证。

## 报告周期精度及同步等值输入

1. 在隔离组织创建合法质量报告计划，记录计划版本及 Quartz 触发器 Cron 和时区。
2. 更新计划时在原始 JSON 将 `periodDays` 设为 `1.5`、`10.0000000000000001` 或数字字符串；也可在计划同步资料中测试 `10.0` 和 `1e1`。
3. 按批准规则，小数和数字字符串应返回400，计划版本、成功审计、触发器 Cron 与时区不变；精确等值的10.0和1e1应作为10接受。报告修复前未保留独立红测，不将本段静态发现冒充动态复现。

页面修复前4个测试方法中2通过、2失败，复现任务进度或报告周期为空时仍发写请求；各循环后续变体未在红测中运行。新回归用 MockMvc、隔离数据库和组件夹具；它们不等于已部署环境的浏览器验收。
