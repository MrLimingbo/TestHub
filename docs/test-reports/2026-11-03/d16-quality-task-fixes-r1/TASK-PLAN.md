# D16 任务进度测试设计（执行前）

依据 D16-AC-25/26/28/29/33、字段矩阵和规则 A：任务 PUT 必须提供 `progress`，数值为 0..100 的精确整数，JSON number 的 `10`、`10.0`、`1e1` 均接受。合法进度检查之后，QUEUED 归0，SUCCEEDED归100；版本与项目权限保持原规则。任务迁移和同步中的 progress 同样不得进行有损转换，并遵循原子性与原有状态约束。

|设计|输入及步骤|预期|
|---|---|---|
|T01|PUT RUNNING 使用 0、100、10.0、1e1|精确保存对应整数|
|T02|PUT 缺失或 null progress|400，任务版本与原值、成功审计不变|
|T03|PUT 小数、极小小数、负数、101、溢出、数字字符串、布尔、数组、对象|400，无修改或成功审计|
|T04|PUT QUEUED/SUCCEEDED 的合法进度及各非法进度|合法时归0/100；非法时先拒绝而非被归一化掩盖|
|T05|旧版本和跨项目身份更新|原版本冲突和权限隔离仍生效|
|T06|迁移原始 JSON 精确等值、0/100、状态约束、非法类型、null/缺失及非有限字面量|接受有效值；坏数据不产生任务、回执、成功审计，错误安全定位|
|T07|同步原始 JSON 精确等值、0/100、状态约束、非法类型、null/缺失及非有限字面量；批次先合法后非法|接受有效值；坏数据不产生部分任务或回执，原状态规则保持，错误安全定位|
|T08|正常请求保持 expectedVersion 原有解析及存量任务读取|非目标字段与旧数据保持原契约|

采用隔离 H2/MySQL 和 MockMvc 原始 JSON 请求，不使用共享数据库。用例结果以可执行方法及其实际测试记录为准。
