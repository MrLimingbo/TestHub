## 1. 保存跨平台专属定位器

前提：有项目写权限，使用隔离项目。

1. 对 `POST /api/v1/projects/{projectId}/mobile-automation/elements` 提交 `{"name":"QA元素","platform":"ANDROID","locatorStrategy":"IOS_PREDICATE","locatorValue":"qa-only","description":""}`。
2. 修复前B02首个请求返回200，非法元素被保存；测试预期400而失败。
3. 修复后返回400且错误说明定位策略与平台不匹配；元素与成功审计数量不增加。iOS配Android UiAutomator反向组合也拒绝。
4. 使用矩阵内通用策略或本平台专属策略应成功；编辑接口携带旧expectedUpdatedAt提交非法组合也必须拒绝且旧值与时间戳不变。

## 2. 非法旧元素被场景和新执行接受

2. 仅在自有测试数据库把元素策略改为IOS_PREDICATE，模拟旧非法资产。
3. 修复前B03的场景创建仍200，B04的新执行仍成功入队；它们分别在首个反例断言失败。
4. 修复后旧元素列表仍可读，场景新增/编辑和新入队受控拒绝；不新增场景、执行、manifest或outbox，不批量修正旧元素。

## 3. 旧排队清单缺少平台匹配预检

1. 用合法ID元素场景入队，取得自有执行的冻结清单。
2. 在自有数据库将清单步骤定位策略改为IOS_PREDICATE，保留Android设备平台。
3. 调用控制面的运行配置发放服务。修复前B06未抛出预期拒绝，说明配置可继续发放。
4. 修复后发放前400，原执行仍QUEUED，清单和数量不被改写；未知/缺失策略、缺失平台及缺失定位值也覆盖。
5. 对照：合法清单入队后仅把源元素改错，旧合法冻结清单仍可发放且内容不变（B07）。不自动取消已运行任务。

1. 从隔离来源导出合法矩阵元素，构造迁移资料；在列表末尾追加跨平台元素。

4. 修复后两入口400，目标资料、迁移/同步回执及成功审计计数保持；合法8组合导入和同步仍成功。

1. 受控fetch夹具向实际AppiumRunner.handle返回Android设备及IOS_PREDICATE的TAP运行配置。
