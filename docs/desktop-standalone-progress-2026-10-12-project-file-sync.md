## 使用与边界

桌面“项目设置 → 文件管理”和应用菜单增加“项目文件同步”。先登录账号服务，选择本地／账号项目，读取两端已有文件，按文件 ID、大小和 SHA-256 逐一确认对应。配对只允许内容相同的文件，原物理 ID 保留；未配对文件各自复制到另一端，即使同名也不会覆盖。新上传文件继续双向复制，保留原文件名、MIME 类型和字节内容，来源键避免重启后的重复复制。

按用户确认，**已同步文件在一端删除或重建时，只暂停该文件并提示人工核对**；不自动重建或删除另一端，其他新文件仍可同步。内容不同或来源标识冲突同样暂停对应文件。重新绑定时要再次确认已有文件；解除绑定保留两端文件。应用运行时每 30 秒检查，可立即同步、暂停和恢复；备份恢复后绑定持久暂停并要求重新预览。

每项目最多 1000 个文件、单文件最多 20 MiB；本轮每次最多处理 100 个文件，余量下次检查继续。超限显式拒绝，不截断内容。同步的是项目文件库本身；需求、用例、计划、缺陷和执行历史正文中的本端文件下载链接**仍由原有模块阻断，尚未跨端重写**。这需要独立的引用映射／预览阶段，不能因文件字节到达目标就宣称引用可用。

## 协议与保护

新增 `GET/POST /api/v1/projects/{projectId}/files/sync`，`PROJECT_FILE_SYNC / 1`。H2 V37／MySQL V94 为 `file_object` 增加可空来源键和 SHA-256，并增加项目内来源唯一索引与持久提交回执。旧文件在首次同步快照时核验实际字节和记录大小、补齐摘要；旧上传、下载、删除和一次性迁移接口保持兼容。

每次上传一个文件，读取来源时再次核验实际大小和 SHA-256；目标端校验请求字节、摘要、预期项目修订、实际账号及项目写权限。文件内容仅通过两端已认证的项目下载路由获取，不抓取任意 URL。目标对象、元数据、审计及回执在原有持久文件迁移清理机制保护下提交；响应丢失后相同请求回执可重放，已提交后删除的文件也不会因重试悄悄重建。HTTP 请求上限 29 MiB，以覆盖 20 MiB 原始文件的 Base64 封装；响应最多 1 MiB。

本机 `project-file-sync.bin` 使用 OS 加密、原子保存和 0600 权限，保存配对、物理 ID、冲突及待提交的完整请求。会话、CSRF、账号服务切换、非可信 IPC 帧、磁盘写失败和恢复备份均有边界检查。远端页面只能打开原生工具，读取／提交由可信原生页发起。
