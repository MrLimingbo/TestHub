# 接口自动化只读执行历史双向同步（已审核通过）

用户已确认“按只读历史同步推进”。本模块按该范围实现 `API_AUTOMATION_HISTORY_SYNC / 1`：显式绑定本地项目和账号项目后，双向保存已结束执行的脱敏报告。原执行端继续管理自己的 Runner 任务，结束后迟到的结果可更新对应副本。导入记录存入独立归档表，不进入执行队列，不创建、取消或重新执行任务，不改写原始执行。正在运行的任务不复制。

报告保留执行时的场景名称、来源场景版本、配置版本／数据行、状态和固定结果代码、提交／开始／结束／截止时间、HTTP／步骤／脚本／并行结果、汇总和清单摘要。协议排除请求地址、请求与响应正文、变量值、密钥、日志内容、Runner 身份、请求人及内部清单路径。按来源项目与执行标识对应，同名执行不会合并；来源版本不替换成目标当前场景版本，历史不依赖目标端已有场景、环境或文件。

接口自动化页和原生菜单新增“历史同步”入口；测试报告提供独立的“同步历史”列表、只读详情及脱敏下载，即使项目没有当前场景也能查看。报告内容 SHA-256 和整个下载文件的 SHA-256 分别校验对应范围。任务中心的统一列表新增“接口自动化同步历史”来源，与原有本端执行区分；原有执行接口、取消逻辑、Runner 队列和统计保持原来的行为。

索引采用轻量来源修订，包含原执行更新时间、清单摘要和后续结果到达信息；只在需要更新时读取报告正文，单条读取按执行 ID 查询，不重复载入全部报告。最多 1000 条来源历史，超过范围明确暂停，不静默截断。每批最多 20 条、4 MiB，单条最多 1 MiB。明细沿用现有报告每类最多 300 条的范围，汇总保留完整计数。索引与完整报告之间以及提交前重新检查变化，避免用新总体修订绕过单条目标冲突。

不同来源副本和已经同步后缺失的历史暂停核对，无关历史继续处理；不自动删除或重建。真实执行端存在时，以它后续生成的报告更新只读副本，不能用同步报告反向改写真实执行。没有原执行端且两个副本不同，不开放手工改写结果。桌面基线只保存轻量索引，待确认请求和状态加密保存；响应丢失后用原请求重试，稳定回执避免重复归档。账号／服务变化停止写入，恢复备份后持久暂停并要求重新绑定。

新增 H2 V41／MySQL V98 的项目归档和幂等回执表。同步具有项目与账号权限、CSRF、项目锁、目标修订和整批事务保护，拒绝未知值字段、活动状态、摘要不一致及对本项目真实执行的覆盖。前置 4 MiB 请求限制覆盖声明长度与 chunked 请求；批次迟发冲突会回滚先前写入。

验证完成：隔离 H2 全量 605 项、独立 MySQL 8.4.10／Redis／文件存储定向 44 项、前端全量 297 项、桌面 525 项通过；最终入口／历史面板再通过定向 9 项，lint、类型检查及生产构建通过。定向回归覆盖多于旧列表 100 条的历史索引、活动任务排除、迟到 HTTP／步骤／脚本结果、回执重试、同来源不同内容回滚、权限与下载完整性；桌面覆盖分批、来源与目标变化、缺失、不同副本、账号变化及备份恢复暂停；前端覆盖项目切换和迟到响应隔离。

源码桌面与内部 Mac arm64 包各通过 8 项真实离屏流程：本地真实 HTTP／脚本成功、独立账号真实超时、双向绑定、网页只读详情及下载校验、旧事实保留与后续真实执行追加、暂停恢复、解绑重绑和加密状态。每组流程恰好 3 个已授权临时回环目标请求，同步没有额外请求或原生任务。两者各通过 3 项真实 V40→V41 升级检查，原账号／记录 ID、公共步骤及固定引用、接口、文件字节与加密同步文件保留，基线数据库未改动。234 个包内原生、后端及生产资源文件 SHA-256 与当前构建一致。

所有窗口隐藏、不可聚焦且离屏，可见窗口违规和意外弹窗均为 0。本阶段测试账号、工作区、数据库、备份、日志、基线、临时包、测试报告及旧运行时副本已清理，仅保留脱敏摘要和复用脚本，见 `.testhub/api-automation-history-sync-module-20261013/final-verification.json`。当前运行时与用户数据保留，未提交或推送 Git。
