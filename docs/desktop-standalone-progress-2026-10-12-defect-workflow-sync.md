## 实现与使用边界

桌面“缺陷与交换”页及应用菜单新增“缺陷工作流同步”。本地与账号模式可以打开独立绑定页，网页端继续使用原有缺陷操作。连接账号服务并登录后选择两端项目，预览不写业务记录；确认默认取消。启用后应用运行期间每 30 秒检查，可立即同步、暂停／恢复、解除绑定及逐条核对冲突。页面直接显示中文状态、确认与解决方案。

按不可变缺陷编号匹配本端实际 ID，同步完整状态组合。激活／处理中必须清空解决方案，已解决／已关闭必须指定合法方案，确认支持显式取消。首次状态不同或双端修改均需人工选择；确认期间状态或实际对象 ID 再次变化会拒绝旧选择。同编号重新创建后工作流不同需重新核对，相同工作流可刷新基线。缺陷缺失会阻断相关工作流，本模块不创建缺陷、不传播删除；须先同步缺陷基本资料并核对。

正文、目录、严重程度、优先级、来源、外部链接、负责人、指派人、抄送、创建信息、三类资产关联、版本和执行历史保留各端。更新人及审计记录本端实际同步账号。人员 ID 没有跨端可靠映射，负责人／抄送持续同步留待独立模块。

同步状态不等同于本端人员实际执行解决／关闭操作，不复制另一端的历史人员和时间，也不生成虚假的本端解决／关闭历史。相同工作流不更新旧记录；只变更确认时保留本端已有历史。已解决与已关闭之间切换且解决方案相同，可保留本端已有解决人员和时间；新关闭不生成关闭归因，退回已解决清除关闭归因。解决方案变化使旧解决／关闭归因失效；激活／处理中清除失效解决／关闭字段。这些规则仅适用于新同步写入，既有手动解决／关闭操作与显式迁移契约保持原有行为，审计历史不删除。

## 协议与兼容保护

新增 `GET/POST /api/v1/projects/{projectId}/functional/defect-workflow/sync`，协议 `FUNCTIONAL_DEFECT_WORKFLOW_SYNC` / 1。定义仅含 `status`、`confirmed`、`resolution`，快照包含各端对象 ID；回执返回提交时对象 ID。每项目最多 100 条缺陷，合并数量包括待核对的缺失基线；快照／合并不超过 3 MiB，请求／响应不超过 4 MiB。严格校验编号、状态组合、布尔值、重复操作、未知与受保护字段，不裁剪超限项目。

H2 V33 / MySQL V90 新增持久回执表，旧迁移不修改。读取使用 REPEATABLE READ 一致快照；写入使用共享项目锁与 READ COMMITTED，等待锁后重新检查包含真实对象及本端历史归因的快照版本。整批预校验、工作流字段写入、审计与回执同事务，失败回滚。专用 SQL 只更新工作流字段与更新人；相同定义不改写旧记录和时间。响应丢失后以原请求重放持久回执，不覆盖之后的手动修改；应用／账号 JVM 重启和同编号重建仍受保护。

新增独立 OS 加密文件 `functional-defect-workflow-sync.bin`，原子写入、权限 0600。损坏保留原文件并报错，不回退为空。可信原生页可操作绑定；远程业务页只可打开原生入口，不能直接操作同步控制。账号或服务切换停止出站修改。十四种同步独立共存，恢复备份前全部持久暂停并要求解除旧绑定、重新预览。

主要实现：`FunctionalDefectWorkflowSyncService.java`／控制器、`FunctionalDefectService.updateWorkflowFromSync`、`FunctionalDefectRepository.updateWorkflow`、`functional-defect-workflow-sync.cjs`／IPC／原生 UI、主进程与两份 preload、桌面导航入口及新回执迁移。新增后端流程、桌面引擎／preload、前端入口和请求体限额回归。
