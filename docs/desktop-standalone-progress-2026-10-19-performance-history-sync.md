本模块已完成实现、后台验收和本阶段测试数据清理，并获用户审核通过。代码与文档已提交 GitHub `main`，提交为 `671ede56147bdfc920b3bd5ebc88c7022d0ddee8`；随后继续[原始 JTL／日志同步模块](desktop-standalone-progress-2026-10-19-performance-artifact-sync.md)。上一模块的提交为 `2a16bcaf98f9300e4470f13fc3212930481810ed`。

## 本轮范围

桌面“性能测试”新增“历史同步”入口及原生绑定窗口。明确选择本地项目、账号项目并确认后，每 30 秒双向检查已结束执行的只读报告；也可立即同步、暂停、恢复或解除绑定。网页端和本地端在“同步历史”查看报告，任务中心单列“性能同步历史”。

同步保留来源项目／执行标识、执行时的计划名称与版本、状态与结果代码、原始时间、数值汇总、性能指标、资源采样及质量阈值结论。来源不同的同名计划不会合并执行；目标端无需先拥有对应的当前计划。原计划编辑不改写已有历史，迟到指标由原端更新同一来源副本。

不传输目标 URL、请求头、请求正文、数据集、密钥、Runner 身份、错误文本、原始日志或 JTL。原生执行、原始工件下载及质量统计保持原有行为。同步不创建、取消或重放任务，导入的历史不重复计入质量汇总。JTL／日志等原始工件的跨端策略留待单独模块，不能将本轮报告同步算作原始工件同步已完成。

## 一致性与数据约束

- 来源键为项目标识加执行标识；每项目最多 1000 条来源历史，超过上限暂停并说明原因，不截断复制。
- 单份报告最多 1 MiB，每批最多 20 条、4 MiB；传入 JSON 在解析前同时限制声明长度和流式长度。
- 指标与资源采样沿用现有原生报告各最多 2000 条的范围，汇总也继承现有报告口径；不宣称覆盖超过该范围的全部采样。
- 报告内容使用 SHA-256 校验；导出另带整文件摘要。SQL 小数去除尾零后参与摘要，保证 Java 与桌面 JSON 编码一致。
- 索引修订包括迟到指标和资源采样的数量及写入时间。发送前复核来源，提交前复核目标；持久化原请求及请求标识，响应丢失后重试同一请求。
- 原端记录禁止被导入报告覆盖。已同步历史缺失、两个脱离原端的副本不同，均暂停相关来源并提示核对，不自动删除或重建。
- 权限、账号、项目及服务绑定均需匹配；查看者不能导入。同步状态加密保存，备份恢复前持久暂停并要求重新绑定，重启后仍生效。
- 时间保留毫秒精度原值。数据库可能将提交时间向上取整，而 Runner 截断事件时间，因此仅允许 1 毫秒的顺序差；更大的倒序拒绝导入。

新增 H2 `V43__performance_history_sync.sql` 与 MySQL `V100__performance_history_sync.sql`，只增加历史归档和幂等回执表。

### 验证中发现并处理的问题

1. 新增历史抽屉后，旧前端测试选中了第一个抽屉，已改为定位当前打开的抽屉，继续验证关闭后的迟到响应隔离；未移除原断言。
2. 备份工具测试的最新数据库版本断言由 42 更新至 43。
3. 修复历史摘要的小数尾零差异和提交时间的 1 毫秒取整边界，新增专项回归。
4. 早期原生 MySQL 专项启动脚本扩展到普通集成测试时，未设置普通数据源，尝试默认端口后因连接拒绝而失败；未建立该连接。已显式将普通数据源、测试专用数据源、存储和本地目录全部指向同一次新建的隔离环境，最终 60 项通过并移除独立 MySQL／Redis。
5. 修复 QA 清理脚本中的 Mac Keychain 账号名：Chromium 使用应用名加 ` Key` 后缀。当前中断尝试的专属条目已删除，最终同步流程的专属条目也已逐一查询确认不存在；未删除用户实际应用的 Keychain 数据。
