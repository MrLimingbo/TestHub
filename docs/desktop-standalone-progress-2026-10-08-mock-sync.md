# TestHub 安装即用：Mock 服务与规则离线双向同步

日期：2026-10-08。上一模块“通知模板离线双向同步”已获用户审核通过。本轮实现与验证已完成，并于 2026-10-08 获用户审核通过；其余范围继续保留待办。

## 使用与范围

桌面 Mock 页及应用菜单新增“Mock 同步”。连接账号服务并登录后，选择本地和账号项目，预览上传、下载、冲突及排除的公开密钥/分享数量，经默认取消的原生确认建立绑定。默认不启用，一组项目绑定；任务登记、项目配置、通知模板、Mock 四种绑定可独立共存。

按服务名称以及所属服务下的规则名称匹配。同步服务容器及规则的方法、路径、优先级、请求参数/头/体条件、响应状态/头/正文。两端已有同名不同内容，以及同一规则两端同时修改，保留双方并要求选择；确认期间规则再次变化则停止。不同规则可独立合并，名称大小写不同需手动统一。所属服务缺失、改名或大小写不一致时，连同新增子规则一起停止，避免错误恢复父服务。MySQL 的其他名称排序/唯一约束冲突返回 409，整批回滚，需手动统一名称。

公开访问密钥、分享链接及历史、服务/规则启停、智能示例开关和接口来源保留各端。新服务生成目标自己的访问密钥并停用，新规则停用，不创建分享。已启用的现有规则未来使用更新后的定义，绑定确认中明确说明。请求匹配条件及响应内容会发送到所选账号服务，界面要求核对其中业务信息。同步不上传其他测试资产，不执行脚本。

Mock 规则补齐编辑及独立启停接口和界面。编辑保留标识、创建信息与启停；项目/服务切换或取消编辑会使等待中的保存失效，迟到完成不能关闭后续编辑器。复制后用户可在界面分别启用规则与服务，再实际调用。请求条件和响应内容编辑器补齐表单内宽度，避免代码区域在弹性布局中被压缩。

应用运行时每 30 秒检查双向新建和更新，断网仍可本地编辑和调用，联网并恢复绑定账号会话后自动重试。支持立即同步、暂停、恢复、解除绑定和冲突选择。删除不传播、不自动重新创建；规则改名按新名称处理，原名称缺失提示核对。退出应用后不后台运行。每项目最多 20 个服务，每服务 200 条规则；快照最多 3 MiB，请求/响应最多 4 MiB。基线中的缺失资料也计入合并数量。

## 一致性与数据保护

- 新增 `/api/v1/projects/{projectId}/mock/sync` GET 快照与 POST 新建/更新批次，沿用 Mock 写入角色 SYSTEM_ADMIN、ORG_ADMIN、PROJECT_ADMIN、TEST_LEAD、TESTER。校验精确账号、项目权限、CSRF、协议、规范化字段、重复操作/名称和数量/字节边界，拒绝未知字段及尾随 JSON。
- 快照不读取公开密钥或分享链接，只返回排除数量。摘要覆盖服务与规则标识、定义、启停、智能示例开关及更新时间。更新只改规则定义，不修改创建信息和启停。新父服务先创建，操作顺序不影响规则归属。
- 原 CRUD、一次性迁移和同步共用项目锁。过期快照、最终快照超限、审计失败及数据库唯一约束冲突整批回滚。新服务从插入到停用处于同一事务，不会暂时开放公开调用。
- POST 前保存准确请求与 UUID；项目/账号/requestKey 唯一回执保证提交后响应丢失的重试返回原结果，不重复创建、不覆盖后续修改。请求/快照的 Map 字段按键稳定排序，避免 Java 进程重启后排序变化导致同一请求的摘要不同。
- `mock-sync.bin` 在工作区外，经系统安全存储加密、原子落盘，权限 0600；不保存密码、令牌、浏览器凭据或被排除的访问密钥/分享。损坏时保留文件并报错，不静默重置。
- 复用已审核的原生 IPC/HTTP 层，仅信任准确原生页面和主框架；业务页面只有打开入口。服务会话隔离、重定向禁止、请求超时和响应有界，错误不回显后端内部内容。
- 四种同步、迁移、执行设置和备份恢复共用互斥保护。恢复备份在切换数据库前持久暂停四个绑定，并要求重新预览。新模块不改旧同步文件格式。

新增 H2 V23 / MySQL V80 `mock_sync_receipt`。无新增依赖，原迁移协议及公开 Mock 调用协议保持。
