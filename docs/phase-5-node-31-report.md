# 阶段 5 · 节点 31：受限并行请求组

完成日期：2026-07-17

## 已交付

- 场景编排新增 `PARALLEL` 步骤：一个组只能包含 2–5 条独立 HTTP 请求，前端可视化编辑分支方法、地址和安全重试次数。
- 控制面在保存、引用展开、运行时工件和执行清单四层校验并行边界；运行时工件升级至 v5，能力标识升级至 `HTTP_FLOW_CONTROL_SCRIPTS_V2`。
- 独立 API Runner 使用 `Promise.allSettled` 等待所有分支完成，为每条分支写入独立请求序号，同时将脱敏结果归属到并行组的父步骤。
- 新增固定日志 `PARALLEL_REQUESTS_STARTED` 与 `PARALLEL_REQUESTS_COMPLETED`，控制面同样以固定代码和固定消息校验后持久化。

## 安全边界

- 并行组只允许 HTTP 请求；脚本、共享局部变量、条件、循环、提取和断言不得跨越或直接消费并行组。
- 包含并行组的场景禁止前后置 JavaScript；组内只能使用已冻结静态变量，不能使用前序 `EXTRACT` 的 Runner 局部变量。
- HTTP 结果、执行清单、日志和报告继续不含 URL、正文、响应、变量值或密钥。

## 验证范围

- Runner 单元测试覆盖两条分支同时启动、父步骤结果归属、请求序号、固定日志与请求内容脱敏。
- 控制面集成测试覆盖有效并行组、脚本冲突拒绝、并行组后断言拒绝及工件/清单版本升级。
- 前端验证覆盖步骤面板、2–5 分支限制与保存前的安全说明。
