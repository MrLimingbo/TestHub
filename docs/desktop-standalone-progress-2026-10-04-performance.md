# 性能测试模块：本地执行与账号迁移

状态：本轮范围的实现、隔离验收和最终内部包复验完成，待用户审核。审核通过前不进入 Web UI 模块。

## 本轮交付范围

- 本地工作区可通过界面创建、编辑和保存压测计划，使用内置 Java 与隔离的 JMeter Runner 执行。保留恒定、线性、阶梯负载，以及请求方法、请求头、查询参数、正文、断言、内联 CSV、集合点和质量阈值；指标、资源监控、错误归因、历史对比、CSV 报告、JTL/日志下载和取消继续可用。
- 原生“本地资料迁入账号”增加性能入口，复制计划当前配置与当前版本号、线程组顺序和上述配置。新计划和线程组生成新标识，归目标账号项目所有。迁入计划统一为草稿，导入不会提交任何压测。
- 预览只读取本地资料和目标能力，不写入账号项目。确认框显示账号、项目、服务地址、数量及敏感内容提示。快照冻结；10 分钟到期或切换账号/服务后须重新预览。UUID 与快照哈希回执保证原请求重试不会重复导入；同名计划、数量超限或任一配置错误会整批回滚，不覆盖目标记录。名称冲突按业务保存时相同的首尾空格归一规则检查。
- 保留目标 URL 原文，包括 localhost；目标运行器及本地目标授权不复制。用户须核对地址和负载后在网页端将草稿改为待执行。网页端与桌面登录同一账号服务时共享服务端数据；本地迁入属于一次性复制，后续编辑不会自动同步。
- 本轮按已说明的默认范围迁移可编辑计划。执行历史、指标、资源数据、JTL 和日志工件仍留在本地，不上传。本轮不是双向离线同步，也不包含所有历史配置版本；现有性能计划模型只维护当前版本号，执行记录另有冻结配置。
- 本地报告工件区域显示“本地存储”，已有服务模式继续显示“MinIO”。

## 实现位置

- 后端：`performance/PerformanceTransferService.java`、`PerformanceTransferController.java`；新建桌面 H2 V13 和 MySQL V70 迁移回执表；迁移请求大小过滤器加入性能路由。继续通过现有压测计划业务服务验证请求、CSV 和负载约束。
- 协议：`GET /api/v1/projects/{projectId}/performance/transfer/capabilities`、同路径快照 GET 和确认 POST，协议 V1、范围 `PERFORMANCE`，最大资料 32 MiB，HTTP 流式请求另有 33 MiB 上限；未知 JSON 字段和尾随数据拒绝。沿用项目写权限、CSRF 和共享错误结构。
- 桌面：`apps/desktop/app/src/performance-transfer.cjs`、`main.cjs`、预加载桥、原生性能迁移页面与入口。仅可信主页面可打开入口，预览和提交仅接受对应原生页面的主框架；迁移与备份等操作共用互斥锁。
- 页面：`src/pages/PerformancePage.vue`，只调整本地报告存储说明。
