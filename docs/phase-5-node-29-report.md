# 阶段 5 · 节点 29：失败策略的结构化执行报告

## 已交付

- 脱敏执行报告升级为 v4，新增 `failureStrategy.strategy` 与 `failureStrategy.continuedFailureCount`。
- 策略来自不可变执行清单；继续次数仅统计已持久化的固定 `FAILURE_CONTINUED` Runner 日志，避免依赖浏览器状态或用户自定义文本。
- 接口自动化执行详情在报告卡片展示“失败即停止 / 失败后继续”及安全继续次数，CLI/CI 使用同一 REST 报告即可读取。

## 安全边界

- 报告只输出固定枚举和计数，不导出日志消息、脚本文本、断言名称、异常、URL、请求/响应、变量或密钥。
- 日志计数按项目、执行、Runner 来源和固定代码聚合；其他控制面日志或任意不可信字段不会被计入。
- 不增加 Runner 权限、任务消息字段或数据库迁移；Runner 仍只通过既有固定日志事件表达继续执行。

## 验证

- 控制面集成测试覆盖 `STOP` 报告默认值、`CONTINUE` 的两个固定继续事件聚合，以及报告中不出现固定日志消息或请求地址。
