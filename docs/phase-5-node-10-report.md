# 阶段 5 · 节点 5.10：单任务短时运行时租约

## 交付内容

- 已验证 Runner 可为一个已投递、未过期的执行任务请求一次短时租约。
- 租约请求的 HMAC 绑定 `taskId` 与 `executionId`，并继续使用时间窗口和 Redis nonce 防重放。
- 租约由 32 字节随机值生成，只在内网响应中返回一次；Redis 仅保存 SHA-256 哈希及无敏感元数据，TTL 不超过 5 分钟且不晚于执行截止时间。
- 每个执行只允许领取一次；重复领取返回冲突，篡改、未投递、终态或过期任务被拒绝。
- Runner 协议提供构造租约请求的能力，但当前 `executionEnabled=false`，不会自动领取租约。

## 安全边界

- 租约不是配置包，不包含场景、请求、变量、环境密钥、认证信息或脚本。
- 本节点不新增配置读取端点、不下发任何敏感值，也不启用网络请求或用户内容执行。
- 后续配置领取必须再次校验租约哈希、Runner、执行、项目范围、任务版本与有效期，并在领取后立即失效。

## 验收建议

1. 打开接口自动化页，确认 Runner 面板明确显示“单任务短时租约仅为后续配置领取预留”。
2. 确认当前本地未配置签名密钥时，Runner 仍显示“未配置校验”，不能领取租约。
3. 通过集成测试验证首次可信领取成功、第二次领取冲突、篡改签名返回 401，且 Redis 值不含响应中的租约明文。
