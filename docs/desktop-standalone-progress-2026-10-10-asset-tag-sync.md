# TestHub 安装即用：功能资产标签关联同步

日期：2026-10-10。上一模块“治理定义同步”已获用户审核通过。本轮仅推进需求、用例、计划的标签关联编辑与持续同步。实现、最终验收和阶段清理已完成，已于 2026-10-10 获用户审核通过。

## 使用与范围

资产治理页新增“资产标签关联”编辑区域，可选择需求、用例或计划，读取当前标签集合后保存；取消全部标签并保存可解除关联。加载失败时不开放保存，保存失败保留选择。项目或资产类型切换会清空编辑状态，迟到响应不能填入新项目；获取 CSRF 期间切换项目或离开页面会阻止尚未发送的写入。

资产治理页和应用菜单新增“标签关联同步”。连接账号服务并登录后，选择一组本地与账号项目，先预览，再通过默认取消的确认建立独立绑定。默认不上传，应用运行期间每 30 秒检查两端，支持立即同步、暂停/恢复、解除绑定及冲突选择。

| 内容 | 行为 |
| --- | --- |
| 匹配 | 按资产类型与编号定位需求/用例/计划；按精确标签名称重映射本端标签 ID |
| 首次不同集合 | 必须选择完整集合；空集合与非空集合也需选择，不隐式合并 |
| 后续编辑 | 同步完整集合，主动清空会解除目标资产关联 |
| 双端编辑 | 暂停相关资产并选择版本；确认期间变化拒绝过期选择 |
| 引用缺失/改名 | 暂停相关资产，先核对基础资料或治理定义；不自动创建资产、标签或传播字典删除 |
| 同名记录重建 | 缓存两端各自的资产/标签 ID；重建且集合不同需核对，包括两次轮询之间发生的删除重建 |
| 缺失引用恢复 | 两端集合仍不同时必须重新选择，避免把删除造成的空集合解释为普通清空 |

两端均已有且相同的集合可直接作为基线。同一编号按资产类型分别隔离。本轮保留正文、资产 ID、创建信息、人员、自定义字段、计划用例顺序、执行快照、文件和历史。标签颜色及字典定义仍由已有治理定义同步处理，基础资产仍由已有基础资料同步处理，原协议保持。已删除资产留下的旧关联不复制，也不清理用户数据。

每项目每资产类型最多 100 个资产，每资产最多 100 个标签名称，引用字典最多 100 个标签。快照及合并后的完整快照最多 3 MiB，POST 与原生响应最多 4 MiB；UTF-8 字节限制与数量/名称长度独立校验，原 CRUD 容量保持。资产编号及标签名称会发送到所选账号服务，预览与确认披露此范围及清空行为。

## 一致性与保护

- 新增 GET/POST `/api/v1/projects/{projectId}/functional/asset-tags/sync`，协议版本 1，范围 `FUNCTIONAL_ASSET_TAG_SYNC`。
- 快照包含所有现存三类资产的集合（包括空集合）、可用标签名称和本端引用 ID；业务操作仅携带编号与名称，不能携带来源 ID、正文或执行数据。
- 写入使用 READ_COMMITTED 与已有功能模块项目锁。摘要包含资产 ID/编号、标签 ID/名称及完整集合；等待锁后重新比较，整批引用验证完成后才替换关联。
- 项目写入权限、绑定账号及 CSRF 校验仍强制执行。审计、关联与持久回执属于同一事务；失败整批回滚，相同请求重放不会重复替换或撤销后来的编辑。
- 新增 H2 V29 / MySQL V86 `functional_asset_tag_sync_receipt`。无变化的操作保留关联记录 ID，资产与标签定义不改写。
- 第十份独立文件 `functional-asset-tag-sync.bin` 使用系统加密、原子写入和 0600 权限。退出应用停止同步；恢复备份前十种绑定全部持久暂停，恢复后必须解除旧绑定并重新预览。
