## 已准备的远程验收

- `build-install-baseline.mjs` 从固定提交创建隔离旧基线，拒绝复用不同的桌面壳源码，构建后移除源码和数据库。
- `build-install-fixtures.mjs` 保留完整产品配置、现有完整性与分发钩子，准备旧版安装器；CI 候选直接使用实际预览安装器，基线只作为临时测试工件。
- `accept-installed.mjs` 在全新原生 Runner 使用真实应用名和精确默认安装／数据路径。已有应用、数据、卸载注册项或快捷方式会使验收拒绝执行，不接管用户数据。
- Windows 分支使用原项目的 assisted NSIS `/S`，检查默认安装目录、快捷方式目标、卸载注册项、静默安装不自动启动应用、升级保留和卸载／重装恢复。该分支尚未在 Windows 实际执行。
- `desktop-release.yml` 已增加三架构安装验收步骤，保留原有正式分发、签名与发布条件，`distributionReady=false`。

系统默认路径依据 [Electron app API](https://www.electronjs.org/docs/latest/api/app)，NSIS 默认行为依据 [electron-builder 文档](https://www.electron.build/nsis/)及项目锁定版本的安装器模板核对。新测试仅涉及构建／验收脚本与文档，没有修改生产业务接口、页面、数据库或桌面业务源码。
