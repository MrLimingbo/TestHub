# 接口模块：调试历史与回放草稿显式迁移

状态：V3 历史迁移已通过源码与内部 Mac arm64 包专项复验。接口测试模块整体尚未完成，不进入下一模块。

## 实现与边界

`ApiHistoryTransferService` 按项目导出全部调试历史，而非页面最近 100 条。导出权限与原历史接口一致，要求项目参数写权限；读取前按数据库存储字节估算限制 8 MiB，最多 5000 条，超限或解密失败直接阻断，不截断或静默跳过。

原生接口迁移 V3 新增默认关闭的“调试历史及回放草稿”选项。预览与原生确认明确提示草稿可能包含认证凭据和请求正文；改变选项必须重新预览。默认导出仍为 V1，capabilities.version 保持 1，支持版本列表扩展为 1/2/3。

源端解密草稿，目标端使用自己的密钥重新加密；迁入记录生成新 ID、归当前目标账号，保留原历史时间、状态及结果，并记录来源项目和历史 ID。页面显示“迁入历史”。导入和点击历史加载草稿均不自动执行请求，不冒充目标新执行。历史请求地址保持原值，草稿中的文件和 gRPC 描述符引用按目标 ID 重写；环境及变量依赖缺失会阻断。全部资产、历史、引用和幂等回执在同一事务中处理，失败回滚。

数据库新增 MySQL V66、桌面 H2 V9 两个来源字段。原有新执行插入及历史响应保持兼容。审计仅记录数量，不记录回放正文或凭据。

## 补充：目录状态切换与失败恢复

随后用全新本地及账号数据目录补充真实 Electron 验证，源码和上述内部包各 **5/5**：`preferences-races-result.json`、`preferences-races-packaged-result.json`。测试对真实后端响应施加延迟或模拟一次网络失败，不以假数据响应替代后端写入。

1. 项目 A 读取响应延迟时切换到 B，A 的迟到结果不能覆盖 B 的目录。
2. 复制 A 目录后延迟保存响应，再切换到 B；实际写入保留在 A，B 的状态不变。
3. 第二个独立浏览器先修改服务端状态，旧桌面保存得到真实 409；保留表单输入，不覆盖服务端，明确重新加载后再保存，两边目录均保留。
4. 保存请求网络失败时表单保留、提示错误，服务端没有写入；恢复网络后明确重试，仅保存一次。
5. 旧账号偏好读取延迟期间通过界面退出并登录第二账号；两账号共用同一项目，但第二账号只加载自己的目录，第一账号数据保持不变。

测试脚本最初使用错误的 Arco option 定位器，修正为页面实际 listitem；另一次尝试在保存弹窗遮罩下切换项目被正常阻止，改用没有弹窗的“复制目录”操作测试迟到保存。最终两组成功结果均包含全部 5 项。

首次定向 H2 命令误从服务子目录调用不存在的 `./mvnw`，未启动测试；随后改为仓库根 wrapper，得到上述 24 项成功结果。
